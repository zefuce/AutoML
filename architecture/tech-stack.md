# Технологический стек

Документ описывает используемые зависимости и обоснование их выбора.

## Фреймворки и библиотеки

### AutoGluon

- **Роль:** автоматическое обучение моделей по конфигурации; табличные задачи.
- **Почему:** сильный результат на табличных данных без ручной настройки; встраивается как библиотека, а не внешний сервис.

### FastAPI

- **Роль:** HTTP API, обработка загрузки датасетов, чат с агентом, оркестрация пайплайна.
- **Почему:** асинхронный, удобная интеграция с Pydantic (валидация схем), стандарт для ML-сервисов на Python.

### LangGraph

- **Роль:** управление циклом агента: вызов LLM, инструментов, уточняющие вопросы, завершение диалога.
- **Почему:** явное представление агента в виде графа состояний, понятная логика пайплайна, удобство управления.

### Jinja2 + htmx

- **Роль:** рендеринг веб страницы: загрузка датасета, чат с агентом, просмотр и редактирование конфигурации, отчёты. Htmx обеспечивает интерактивность и стриминг ответов агента.
- **Почему:** использование Python, отсутствие необходимости поддержки второй кодовой базы. Позже возможна замена UI на SPA без изменения архитектуры.

## Управление данными

### Redis

- **Роль:** брокер сообщений для Celery и result backend (статусы и результаты задач).
- **Почему:** одна зависимость закрывает обе потребности; прост в развёртывании.

### PostgreSQL

- **Роль:** история чатов, профили датасетов, конфигурации задач.
- **Почему:** надёжное реляционное хранилище структурированных данных.

### Docker volume

- **Роль:** хранение датасетов и артефактов обучения.
- **Почему:** объёмы данных и топология на текущем этапе не требуют объектного хранилища; использование абстракции в виде ключей вместо путей делает возможную миграцию на S3 незаметной для остальной системы.

## Инфраструктура

### Celery

- **Роль:** постановка задач обучения в очередь, выполнение воркером, отслеживание статуса задачи.
- **Почему:** вынесение обучения в отдельный компонент, чтобы не блокировать API. Даёт встроенные retry и статус задач.

### Docker

- **Роль:** упаковка всех контейнеров системы, декларативный запуск через Docker Compose.
- **Почему:** изоляция тяжёлых зависимостей, контроль воспроизводимости, удобство масштабирования.

## Инструменты разработки

### UV

- **Роль:** менеджер зависимостей и виртуальных окружений Python.
- **Почему:** высокая скорость, воспроизводимость окружения.

### Ruff

- **Роль:** линтер и автоформаттер кода.
- **Почему:** высокая скорость, несколько инструментов в одном.

### MyPy

- **Роль:** статическая проверка типов.
- **Почему:** проверка соблюдения контраков типизированными схемами.

### Pytest

- **Роль:** фреймворк для модульных и интеграционных тестов.
- **Почему:** стандарт для Python, минималистичный синтаксис, фикстуры для подготовки датасетов и моков LLM.

## Внешние системы

### LLM Provider

- **Роль:** «мозг» агента - анализ запроса пользователя, выбор тулов, генерация конфигурации.
- **Почему:** своя модель нецелесообразна по стоимости и качеству; API позволяет менять модель.
