# Таксономии тестовой коллекции

Документ описывает управляемые словари, которыми размечаются сценарии.

> [!NOTE]
> Каждый кейс тегируется по всем таксономиям в манифесте; каждая метрика агрегируется по тегам.

## 1. `data_problems.yaml` - проблемы данных

Первичный словарь; составлен так, чтобы каждая проблема имела проверяемое действие агента и отмечалась в отчётах ручного EDA.

| Группа | Тег | Краткое описание |
| --- | --- | --- |
| Пропуски | `missing_nan` | Формальные пропуски |
| Пропуски | `sentinel_codes` | Спец-коды: `unknown`, `-200`, `pdays = -1` |
| Пропуски | `target_partial_missing` | Часть значений таргета отсутствует |
| Дисбаланс | `class_imbalance` | Редкий положительный класс |
| Утечки | `leakage_post_factum` | Признак известен только после события (`duration`) |
| Утечки | `proxy_leakage` | Прокси таргета, слишком предиктивные колонки (`PageValues`) |
| Структура | `categorical_numeric_codes` | Категории, закодированные числами |
| Структура | `ambiguous_target` | Возможен не один таргет; смысловая, а не формальная неоднозначность |
| Структура | `duplicates` | Повторяющиеся строки |
| Зависимости | `temporal_dependency` | Временная структура наблюдений |
| Зависимости | `group_dependency` | Повторяющиеся объекты (`patient_nbr`) |
| Качество | `outliers_domain_valid` | Выбросы, валидные по предмету (отрицательный баланс) |
| Качество | `inconsistent_categories` | Неоднозначные статусы, неравномерные категории |
| Запрос | `unsupported_task` | Задача вне рамок проекта (кластеризация, TS) |
| Запрос | `conflicting_requirements` | Противоречивые требования пользователя |

Каждый тег снабжается в YAML-файле полями: `description`, `check` (какие инструменты агента должны её увидеть), `default_severity`, `expected_actions[]` (подмножество: `notice`, `ask_user`, `warn`, `exclude_column`, `choose_metric`, `change_split`).

## 2. `request_styles.yaml` - стили запросов

| Тег | Описание |
| --- | --- |
| `structured_full` | Полное структурированное ТЗ: цель, таргет, метрика, ограничения |
| `business_colloquial` | Бытовая формулировка без ML-терминов |
| `terse` | Одно-два коротких предложения |
| `cryptic_slang` | Странные формулировки, жаргон, обрывки фраз |
| `noisy_typos` | Опечатки и шум |
| `metric_explicit` | Метрика названа явно |
| `metric_implied` | Приоритет ошибок описан словами («не пропускать отток») |
| `contradictory` | Внутреннее противоречие требований |
| `out_of_scope` | Неподдерживаемая задача |
| `minimal_no_target` | Запрос без указания таргета |
| `moment_of_prediction_ambiguous` | Неясен момент прогноза (доступность признаков) |

## 3. `preprocessing_ops.yaml` - операции подготовки данных

Словарь операций эталонной подготовки. Ограничен операциями, которые AutoGluon **не выполняет сам**.

| Тег | Описание |
| --- | --- |
| `none_needed` | Пустой эталон: вмешательство не требуется |
| `drop_columns` | Исключение колонок (утечка, идентификатор) |
| `remap_sentinel` | Перекодировка спец-значений |
| `cast_categorical_codes` | Явное указание категориальных типов для числовых кодов |
| `build_target` | Построение нового таргета из имеющихся колонок |
| `filter_rows` | Обоснованное удаление строк |
| `resample_split_strategy` | Требование к способу разбиения |

## 4. `metric_equivalence.yaml` - классы эквивалентности метрик

Грейдер конфигурации не требует точного совпадения `eval_metric`: близкие по смыслу метрики засчитываются полностью или частично. Файл описывает классы и частичный кредит:

```yaml
equivalence_classes:
  - members: [f1, f1_macro, f1_weighted]
    partial_credit:
      - {from: f1_macro, to: f1, when: class_imbalance, credit: 0.5}
  - members: [roc_auc, pr_auc]
    note: "при дисбалансе roc_auc вместо pr_auc — частичный кредит"
  - members: [root_mean_squared_error, mean_absolute_error]
    credit: 0.7
```

Правила:

1. Полный кредит - внутри класса, если в манифесте кейса нет ограничивающего условия.
2. Частичный кредит - задаётся явно парой «отклонение - условие - вес».
3. Всё, что не покрыто классами, считается несовпадением.
