# Переход от запроса к конфигурации

Документ описывает соответствие между результатом [анализа пользовательского запроса](./user_request_analysis.md) и параметрами [финальной конфигурации AutoGluon](./configuration.md).

Анализ пользовательского запроса и конфигурация AutoGluon имеют разные назначения, поэтому их поля не требуется называть одинаково. При формировании конфигурации используется следующее соответствие:

## Таблица соответствий

| Поле анализа запроса | Параметр конфигурации | Правило преобразования |
| --- | --- | --- |
| `goal` | - | Сохранить прикладную цель для проверки и объяснения результата; напрямую в AutoGluon не передавать |
| `target` | `label` | Сопоставить смысловое описание с существующим столбцом датасета; построение нового таргета, если оно необходимо, относится к подготовке данных |
| `task_type` | `problem_type` | Проверить поддержку и согласованность типа задачи с целевой переменной |
| `metric` | `eval_metric` | Проверить название и применимость метрики; при отсутствии выбрать обоснованное значение по умолчанию |
| Приоритеты ошибок | `eval_metric`, `positive_class` при необходимости | Выбрать метрику и положительный класс с учётом смысла ошибок |
| Требуемый уровень качества | `eval_metric` и логика оценки результата | Учитывать цель при выборе метрики; заданный порог качества не гарантируется параметрами AutoGluon |
| `constraints.training_time` | `time_limit` | Перевести ограничение в секунды и проверить допустимый бюджет |
| Требования к признакам | `ignored_columns` | Сопоставить названия с датасетом и проверить исключения |
| Контекст о времени и группах | `validation_procedure` и внешнее разбиение | Проверить зависимости и выбрать корректное разбиение |
| `requirements.interpretability`, требования к сложности, размеру и скорости предсказания | `presets` и дополнительные проверки сервиса | Учесть пожелания при выборе настроек и оценить фактический результат; прямого гарантированного соответствия нет |
| Ограничения вычислительных ресурсов | `num_cpus`, `num_gpus` | Проверить доступное оборудование |
| Пожелания к результату и отчёту | Логика сервиса | Не передавать как аргументы `fit()` |
| Статусы `explicit`, `inferred`, `unknown`, `ambiguous` | Не являются параметрами AutoGluon | Сохранять происхождение требований; неопределённые значения уточнять либо обрабатывать по правилам сервиса |
| `conflicts` | Не является параметром AutoGluon | Зафиксировать противоречия и не запускать обучение, пока не разрешены существенные конфликты |
| Запрос неподдерживаемой ML-задачи | Конфигурация не формируется | Сообщить об ограничении, а не подменять задачу классификацией или регрессией |

Соответствие не означает прямого копирования значений: параметры конфигурации проверяются по данным и приводятся к форматам, необходимым AutoGluon. Требования, не имеющие прямого аналога в API, обрабатываются логикой сервиса.
