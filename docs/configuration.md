# Конфигурация

Документ определяет параметры финальной проверенной конфигурации ML-задачи, которую агент формирует для запуска AutoGluon Tabular. Конфигурация строится на основе [анализа пользовательского запроса](./user_request_analysis.md), свойств загруженного датасета и настроек системы. Названия полей промежуточного анализа запроса не обязаны совпадать с параметрами AutoGluon: их соответствие и правила преобразования описаны в документе [Переход от запроса к конфигурации](./request_to_configuration.md).

> [!NOTE]
> Для структурированного вывода LLM и проверки типов планируется использовать Pydantic. Промежуточное представление требований (`value`, `status`, `conflicts`) не передаётся напрямую в AutoGluon. Перед запуском параметры проверяются, а поля обёртки преобразуются в реальные вызовы API.
>
> Параметры сверены с документацией AutoGluon Tabular 1.6.1. Используемая в проекте версия библиотеки должна быть зафиксирована отдельно.

## 1. Таргет

Определяет, что требуется предсказывать. Значения устанавливаются после сопоставления пользовательского запроса с данными.

#### `label`

- **Тип:** String
- **Допустимые значения:** существующее имя столбца датасета
- **Обязательный в финальной конфигурации:** да
- **По умолчанию:** нет
- **API:** `TabularPredictor(label=...)`

Целевой столбец, значения которого известны на обучающих наблюдениях. Семантическое описание таргета из запроса не считается подтверждённым именем столбца. Если столбец не найден или выбор неоднозначен, запуск откладывается до уточнения.

#### `problem_type`

- **Тип:** String Enum или `null`
- **Допустимые значения проекта:** `binary`, `multiclass`, `regression`, `null`
- **Обязательный:** нет
- **По умолчанию:** `null`
- **API:** `TabularPredictor(problem_type=...)`

Если указан `null`, AutoGluon определяет тип задачи по значениям целевого столбца. При явно выбранном типе требуется проверить его соответствие данным. AutoGluon также поддерживает `quantile`, однако этот тип задачи пока не включён в основной объём проекта. Кластеризация и отдельное прогнозирование временных рядов не поддерживаются.

## 2. Метрики

Определяет, по каким метрикам модель оптимизируется и оценивается.

#### `eval_metric`

- **Тип:** String Enum или `null`
- **Допустимые значения проекта:**
  - бинарная классификация: `accuracy`, `f1`, `precision`, `recall`, `roc_auc`, `log_loss`;
  - многоклассовая классификация: `accuracy`, `f1_macro`, `log_loss`;
  - регрессия: `root_mean_squared_error`, `mean_absolute_error`, `r2`.
- **Обязательный:** нет
- **По умолчанию:** `null` (AutoGluon выбирает метрику по типу задачи)
- **API:** `TabularPredictor(eval_metric=...)`

Основная метрика обучения и выбора моделей. Значение должно соответствовать `problem_type`. Например, пользовательская просьба «не пропускать отток» - требование к типу ошибок, но сама по себе ещё не является указанием `recall`: до выбора метрики нужно определить положительный класс и проверить контекст задачи.

В документации AutoGluon поддерживается больше метрик; выше перечислено осознанно ограниченное подмножество для проекта.

#### `positive_class`

- **Тип:** String, Integer или `null`
- **Допустимые значения:** существующая метка целевого столбца для бинарной классификации
- **Обязательный:** нет
- **По умолчанию:** `null`
- **API:** `TabularPredictor(positive_class=...)`

Положительный класс для бинарных метрик, чувствительных к выбору класса (например, `f1`, `precision`, `recall`, `roc_auc`). При неоднозначности значения требуется уточнение или явно обоснованное правило, а не произвольный выбор.

#### `extra_metrics`

- **Тип:** Array of Strings
- **Допустимые значения:** дополнительные метрики, совместимые с типом задачи, без повтора `eval_metric`
- **Обязательный:** нет
- **По умолчанию:** `[]`
- **API:** `predictor.leaderboard(test_data, extra_metrics=...)`

Дополнительные показатели для отчёта на оценочной выборке, не влияющие на оптимизацию обучения. Это параметр этапа оценки, а не аргумент `TabularPredictor.fit()`. Для расчёта нужен набор данных с известными ответами. При формировании пользовательского отчёта необходимо учитывать формат представления метрик AutoGluon, в частности преобразование знака для метрик ошибок.

## 3. Признаки

Определяет ограничения на использование столбцов и возможную коррекцию их типов.

#### `ignored_columns`

- **Тип:** Array of Strings
- **Допустимые значения:** существующие имена столбцов-признаков
- **Обязательный:** нет
- **По умолчанию:** `[]`
- **API:** `TabularPredictor(learner_kwargs={"ignored_columns": [...]})`

Столбцы, которые не используются как признаки (например, идентификаторы либо подтверждённые утечки). Целевой столбец `label` не может присутствовать в этом списке. Обнаружение возможной утечки должно сопровождаться предупреждением: не всякая утечка определяется автоматически.

#### `type_map_raw` (дополнительный параметр)

- **Тип:** Dict[String, String] или `null`
- **Допустимые значения:** отображение имя столбца → тип, например `{"age": "int", "city": "category"}`; типы сверяются с AutoGluon
- **Обязательный:** нет
- **По умолчанию:** `null` (автоматическое определение типов)
- **API:** используется при создании `FeatureMetadata(type_map_raw=...)`, затем передаётся как `feature_metadata` в `fit()`

Этот параметр не является самостоятельным аргументом `TabularPredictor` или `fit()`. Передача пользовательских переопределений требует подготовки полной согласованной схемы типов; в MVP достаточно автоматического определения типов. Ручное переопределение относится к возможному расширению.

## 4. Валидация

Нужно различать внутреннюю валидацию AutoGluon (для обучения и выбора модели) и независимую отложенную выборку для финальной оценки. Наличие у обучающих объектов временных или групповых зависимостей влияет на корректность разделения.

#### `validation_procedure` (параметр обёртки)

- **Тип:** String Enum
- **Допустимые значения:** `auto`, `holdout`, `bagging`
- **Обязательный:** нет
- **По умолчанию:** `auto`
- **API:** прямого одноимённого аргумента верхнего уровня у `TabularPredictor.fit()` для выбора этих режимов нет; настройка переводится обёрткой в `holdout_frac`, `num_bag_folds` и связанные параметры

`auto` оставляет решение об устройстве внутренней валидации AutoGluon; `holdout` означает отдельную валидационную часть внутри обучающих данных без bagging (`num_bag_folds=0`); `bagging` требует как минимум двух фолдов (`num_bag_folds>=2`). Обёртка обязана обеспечить согласованность режима с `auto_stack` и `num_stack_levels`. Исходное значение `cross_validation` заменено на `bagging`, чтобы не смешивать произвольную внешнюю кросс-валидацию и механизм AutoGluon.

#### `holdout_frac`

- **Тип:** Float или `null`
- **Допустимые значения проекта:** `0 < holdout_frac <= 0.5` либо `null`
- **Обязательный:** нет
- **По умолчанию:** `null`
- **API:** `fit(holdout_frac=...)`

Доля обучающей выборки, которую AutoGluon использует для внутренней валидации. При обычном bagging значение игнорируется, если дополнительно не включён соответствующий режим holdout. Не задаёт долю независимой тестовой выборки.

#### `auto_stack`

- **Тип:** Boolean
- **Допустимые значения:** `true`, `false`
- **Обязательный:** нет
- **По умолчанию:** `false`
- **API:** `fit(auto_stack=...)`

Разрешает автоматический выбор bagging и многоуровневого стекинга. Может значительно увеличить время обучения и предсказания. Явные `num_bag_folds` и `num_stack_levels` имеют приоритет.

#### `num_bag_folds`

- **Тип:** Integer или `null`
- **Допустимые значения проекта:** `0`, целые от `2` до `10`, `null`
- **Обязательный:** нет
- **По умолчанию:** `null`
- **API:** `fit(num_bag_folds=...)`

Количество фолдов для bagging. `0` отключает bagging, `1` недопустим. Значение `null` означает, что явного выбора нет. Число фолдов должно учитывать объём данных и минимальную представленность классов.

#### `num_stack_levels`

- **Тип:** Integer или `null`
- **Допустимые значения проекта:** целые от `0` до `3`, `null`
- **Обязательный:** нет
- **По умолчанию:** `null`
- **API:** `fit(num_stack_levels=...)`

Число дополнительных уровней стекинга. При положительном значении требуется bagging с `num_bag_folds >= 2`.

#### Независимое разбиение на обучающую и тестовую части (логика сервиса)

В MVP сервис должен выделять независимую тестовую выборку до вызова `fit()`, фиксировать способ разбиения и не использовать тестовые ответы для выбора конфигурации или моделей. Для обычных независимых наблюдений возможно случайное (при классификации - по возможности стратифицированное) разбиение. При временной зависимости или повторяющихся группах необходимо отдельное обоснованное разделение либо остановка с предупреждением; эти сценарии не решаются автоматически параметром `holdout_frac`.

Временные и групповые зависимости также необходимо учитывать при внутренней валидации AutoGluon. Для этого в AutoGluon 1.6.1 предусмотрен параметр `validation_structure`. Его использование зависит от структуры данных и выбранных настроек обучения.

Конкретная доля тестовых данных, seed и алгоритмы временного/группового разбиения задаются в реализации сервиса и должны быть зафиксированы для воспроизводимых сравнений. Они не являются параметрами AutoGluon, перечисленными выше.

## 5. Ограничения и требования к результату

Определяет бюджет вычислений и допустимые настройки обучения. Не все текстовые пожелания пользователя имеют прямой параметр AutoGluon.

#### `time_limit`

- **Тип:** положительное число секунд или `null` на уровне API; целое положительное число в конфигурации приложения
- **Допустимые значения проекта:** положительное целое число секунд в пределах лимита среды
- **Обязательный в финальной конфигурации приложения:** да
- **По умолчанию:** установленный лимит приложения, если пользователь не указал свой (конкретное значение требуется закрепить в настройках сервиса)
- **API:** `fit(time_limit=...)`

Ориентировочный бюджет обучения, а не строгий предел времени всей обработки запроса. Время загрузки данных, диалога, внешнего разбиения и расчёта отчёта учитывается отдельно. Если требование пользователя меньше минимально разумного бюджета, сервис должен сообщить об ограничении, а не обещать гарантированный запуск.

#### `presets`

- **Тип:** String Enum
- **Допустимые значения проекта:** `best_quality`, `high_quality`, `good_quality`, `medium_quality`, `optimize_for_deployment`, `interpretable`
- **Обязательный:** нет
- **По умолчанию:** `medium_quality`
- **API:** `fit(presets=...)`

Профиль настроек AutoGluon. Для первого MVP уместно оставить стандартный `medium_quality`; расширенный выбор профиля следует проверять на датасетах. `interpretable` не гарантирует, что любое объяснение модели будет понятным пользователю. В API существуют и другие пресеты, не входящие в основной набор проекта. Использование отдельных профилей может требовать дополнительных зависимостей или ограничивать доступность некоторых результатов обучения. Перед запуском необходимо проверять совместимость выбранного профиля с настройками сервиса.

#### `excluded_model_types`

- **Тип:** Array of Strings
- **Допустимые значения проекта:** коды семейств моделей, поддерживаемые закреплённой версией AutoGluon (например, `GBM`, `CAT`, `XGB`, `NN_TORCH`, `FASTAI`, `RF`, `XT`, `KNN`)
- **Обязательный:** нет
- **По умолчанию:** `[]`
- **API:** `fit(excluded_model_types=...)`

Исключает выбранные семейства моделей. Перед запуском следует проверять названия на совместимость с установленной версией и доступными зависимостями.

#### `num_cpus`

- **Тип:** Integer или String
- **Допустимые значения:** `auto` или целое число `>= 1`
- **Обязательный:** нет
- **По умолчанию:** `auto`
- **API:** `fit(num_cpus=...)`

Ограничивает число ядер CPU, выделяемых AutoGluon; значение не должно превышать доступные ресурсы среды.

#### `num_gpus`

- **Тип:** Integer или String
- **Допустимые значения:** `auto` или целое число `>= 0`
- **Обязательный:** нет
- **По умолчанию:** `auto`
- **API:** `fit(num_gpus=...)`

Ограничивает число GPU. Значение `0` запрещает использование GPU; выбранные модели и пресеты должны быть совместимы с доступным оборудованием.

## 6. Окружение

Параметры, управляемые преимущественно приложением, а не извлекаемые из запроса пользователя.

#### `path`

- **Тип:** String или `null`
- **Допустимые значения:** путь к каталогу результатов, созданному и разрешённому сервисом
- **Обязательный:** нет
- **По умолчанию:** `null` на уровне AutoGluon; в сервисе рекомендуется отдельный каталог для каждого запуска
- **API:** `TabularPredictor(path=...)`

Папка для моделей и промежуточных результатов. Нельзя без проверки принимать произвольный путь из пользовательского запроса.

#### `verbosity`

- **Тип:** Integer
- **Допустимые значения:** `0`, `1`, `2`, `3`, `4`
- **Обязательный:** нет
- **По умолчанию:** `2`
- **API:** `TabularPredictor(verbosity=...)`

Уровень подробности сообщений AutoGluon. Для оценки агента сервис дополнительно сохраняет исходный запрос, промежуточное представление, итоговую конфигурацию, уточнения, предупреждения, метрики и ошибки выполнения. `verbosity` не заменяет такое логирование.

## Переход от запроса к конфигурации

Анализ пользовательского запроса и формирование конфигурации AutoGluon представляют собой последовательные этапы работы системы. Соответствие извлекаемой информации параметрам конфигурации и правила их преобразования приведены в документе [Переход от запроса к конфигурации](./request_to_configuration.md).

Промежуточные значения могут оставаться текстовыми и содержать статусы источника информации. В финальной конфигурации используются проверенные значения и типы; сведения, отсутствующие в запросе, могут быть заполнены по правилам сервиса. Если требование нельзя выразить доступными параметрами или проверить автоматически, система должна явно сообщить об этом, а не считать требование выполненным. Например, `target = "стоимость квартиры"` преобразуется в `label = "SalePrice"` только если этот столбец соответствует цели пользователя, а `constraints.training_time = "не больше 10 минут"` - в `time_limit = 600`.

Порядок обработки:

1. Анализ запроса формирует значения со статусами `explicit`, `inferred`, `unknown`, `ambiguous` и список конфликтов - без подстановки предположений за слова пользователя.
2. Сервис проверяет данные: наличие и смысл целевого столбца, совместимость типа задачи и метрик, доступность признаков, возможные утечки, ограничения на разбиение.
3. Для обязательной информации с неразрешённой неоднозначностью или конфликтом запрашивается уточнение либо выдаётся объяснение невозможности корректного запуска. Для остальных полей применяются подтверждённые правила и значения по умолчанию.
4. Генерируется конфигурация только из разрешённых параметров; Pydantic и логика обёртки проверяют типы, допустимые значения и совместимость параметров друг с другом.
5. Сервис формирует отдельную тестовую выборку, вызывает AutoGluon и оценивает результат на тестовых данных. Все фактически использованные значения сохраняются в логах.

**Пример финальной конфигурации** для случая, когда в датасете действительно есть столбец `SalePrice`, а пользователь ограничил обучение десятью минутами:

```json
{
  "label": "SalePrice",
  "problem_type": "regression",
  "eval_metric": "root_mean_squared_error",
  "extra_metrics": ["mean_absolute_error"],
  "ignored_columns": [],
  "validation_procedure": "auto",
  "auto_stack": false,
  "time_limit": 600,
  "presets": "medium_quality",
  "num_cpus": "auto",
  "num_gpus": "auto"
}
```

Здесь `label` подтверждён по данным, а метрика и профиль выбраны на этапе конфигурирования, не извлечены из исходного запроса. `validation_procedure`, `ignored_columns` и `extra_metrics` требуют описанного выше преобразования обёрткой и не передаются в `fit()` как одноимённые аргументы. Отсутствующие необязательные поля используют оговорённые значения по умолчанию.
