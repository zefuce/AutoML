# BM-02 - Сокращение бесполезных звонков

**Датасет:** Bank Marketing (`bank-full.csv`)  
**Категория:** разговорный  

## 1. Входные данные

**Запрос пользователя:**

> «Короче, не хочу обзванивать всех подряд. Если модель зря отправит менеджера к человеку, которому депозит не нужен, мы только потратим деньги. Сделай так, чтобы таких звонков было поменьше.»

**Вход для будущего теста:** исходный `bank-full.csv` вместе с приведённым выше текстом.

Пользователь описывает приоритет ошибок, но не называет метрику, допустимую стоимость звонка или минимальное количество клиентов, которых нужно охватить.

## 3. Ручное решение и конфигурация

- **Задача:** `label = "y"`, `problem_type = "binary"`, положительный класс `yes`. По EDA доля `yes` - 11,70%; классы несбалансированы.
- **Признаки:** `duration` нельзя использовать для выбора клиента до соответствующего звонка. Нужно уточнить, планируется первый или повторный контакт, и проверить доступность `campaign`, `contact`, `day`, `month` и истории прошлых кампаний. До этой проверки безопасен консервативный набор исключений.
- **Метрика:** `precision` - обоснованный начальный выбор для снижения доли бесполезных звонков среди рекомендованных контактов, но это решение агента, а не названная пользователем метрика. Необходимо также учитывать долю найденных заинтересованных клиентов и цену ошибок. Порог для звонка без бизнес-условий не задаётся.
- **Валидация:** для предварительной оценки возможно независимое стратифицированное случайное разбиение; внутренняя валидация AutoGluon - `auto`. Результат не следует выдавать за проверку на будущей кампании.

**Кандидат конфигурации** (после проверки необходимых условий):

```json
{
  "label": "y",
  "problem_type": "binary",
  "positive_class": "yes",
  "eval_metric": "precision",
  "ignored_columns": [
    "duration",
    "campaign",
    "contact",
    "day",
    "month"
  ],
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

Конфигурация предварительная: список исключений выбран консервативно до уточнения момента звонка. `time_limit` пользователь не задал - сервис подставляет лимит по умолчанию. `ignored_columns` и `validation_procedure` преобразуются обёрткой, а не передаются в `fit()` как одноимённые аргументы.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент определяет `y`, `binary`, класс `yes` и приоритет снижения ложноположительных прогнозов; рассматривает `precision`, проверяет доступность признаков и не назначает произвольный порог обзвона.
- **Допустимые альтернативы:** другая обоснованная метрика или набор метрик; уточнение стоимости звонка, допустимых пропусков заинтересованных клиентов и момента прогноза до окончательной конфигурации. Формулировки и порядок действий не обязаны совпадать с эталоном.
- **Критические ошибки:** оптимизация исключительно `accuracy` без учёта цели запроса; использование недоступных к моменту прогноза признаков; выдуманная стоимость звонка или порог, представленные как требования пользователя; утверждение, что одна метрика `precision` гарантирует экономию.
