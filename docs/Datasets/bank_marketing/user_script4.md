# BM-04 - Бинарная классификация с заданной метрикой и лимитом

**Датасет:** Bank Marketing (`bank-full.csv`)  
**Категория:** явный, ограничения  

## 1. Входные данные

**Запрос пользователя:**

> «Построй модель бинарной классификации для `y`. Для выбора моделей используй `roc_auc`, время обучения ограничь 10 минутами. Решение о звонке принимается до первого контакта с клиентом.»

**Вход для будущего теста:** исходный `bank-full.csv` вместе с приведённым выше текстом.

Метрика и ограничение обучения указаны явно. Положительный класс `yes` устанавливается после проверки данных; пользователь его не называл. Противоречий в запросе нет.

## 3. Ручное решение и конфигурация

- **Задача:** `label = "y"`, `problem_type = "binary"`, положительный класс `yes`. По EDA доля `yes` - 11,70%; классы несбалансированы.
- **Признаки:** исключить `duration`, неизвестный до завершения звонка, и для прогноза до первого контакта консервативно исключить исходные `campaign`, `contact`, `day`, `month`. Проверить доступность других полей до контакта, в том числе `previous`, `pdays`, `poutcome`.
- **Метрика и время:** `eval_metric = "roc_auc"` и `time_limit = 600` секунд. Лимит относится к обучению AutoGluon, а не ко всей обработке запроса; его соблюдение может зависеть от вычислительной среды.
- **Валидация:** внешняя независимая стратифицированная тестовая выборка возможна для предварительной оценки; внутренняя валидация AutoGluon - `auto`. Без полной хронологии проверку нельзя считать тестом на будущей кампании.

**Кандидат конфигурации** (после проверки необходимых условий):

```json
{
  "label": "y",
  "problem_type": "binary",
  "positive_class": "yes",
  "eval_metric": "roc_auc",
  "ignored_columns": [
    "duration",
    "campaign",
    "contact",
    "day",
    "month"
  ],
  "validation_procedure": "auto",
  "time_limit": 600,
  "presets": "medium_quality"
}
```

Кандидат требует проверки доступности оставшихся признаков до первого контакта. `ignored_columns` и `validation_procedure` реализуются через обёртку, а не как одноимённые аргументы `fit()`.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент сохраняет явные `y`, `binary`, `roc_auc` и лимит 600 секунд; устанавливает класс `yes` по данным, исключает `duration`, проверяет доступность признаков до контакта и обоснованно выбирает валидацию.
- **Допустимые альтернативы:** уточнение, что считается «первым контактом», и доступности истории прошлых кампаний; дополнительные исключения признаков при обоснованном риске утечки. Формулировки и порядок действий не обязаны совпадать с эталоном.
- **Критические ошибки:** игнорировать или изменить явно заданные метрику и лимит; использовать `duration` либо недоступные к моменту прогноза признаки; ошибиться с таргетом или типом задачи; представить случайную выборку как проверку на будущих кампаниях.
