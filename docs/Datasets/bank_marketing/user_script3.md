# BM-03 - Неоднозначный запрос о времени согласия

**Датасет:** Bank Marketing (`bank-full.csv`)  
**Категория:** короткий, неоднозначный  

## 1. Входные данные

**Запрос пользователя:**

> «А когда они согласятся?»

**Вход для будущего теста:** исходный `bank-full.csv` вместе с приведённым выше текстом.

## 2. Ручной анализ запроса

Результат извлечения требований из текста:

```json
{
  "goal": {
    "value": "понять, когда произойдёт согласие; объект и смысл вопроса не уточнены",
    "status": "ambiguous"
  },
  "task_type": {
    "value": null,
    "status": "ambiguous"
  },
  "target": {
    "value": null,
    "status": "ambiguous"
  },
  "metric": {
    "value": null,
    "status": "unknown"
  },
  "constraints": {
    "training_time": {
      "value": null,
      "status": "unknown"
    }
  },
  "requirements": {
    "prediction_subject": {
      "value": null,
      "status": "ambiguous"
    },
    "prediction_result": {
      "value": "вероятность согласия или дата/время согласия",
      "status": "ambiguous"
    }
  },
  "conflicts": []
}
```

Неясно, к кому относится «они» и означает ли «когда» момент события, вероятность согласия либо вопрос о произошедших событиях. Это неоднозначность, а не конфликт требований.

## 3. Ручное решение и конфигурация

- **Задача:** пока нельзя однозначно выбрать таргет и тип задачи. Если пользователь имеет в виду вероятность согласия клиентов на депозит, в данных есть `y` с классами `yes`/`no`, и возможна бинарная классификация.
- **Ограничение данных:** датасет не содержит достоверной даты подписки на депозит: `day` и `month` описывают последний контакт, а полный временной ряд событий отсутствует. Поэтому нельзя обещать прогноз даты согласия на основе текущего `bank-full.csv`.
- **Метрика и валидация:** до уточнения цели не выбираются. Если будет подтверждена бинарная классификация, потребуется определить момент прогноза и доступность признаков; `duration` нельзя использовать для прогноза до звонка.

**Кандидат конфигурации:** не формируется до уточнения запроса.

Сначала нужно выяснить, о каких клиентах или событиях речь и требуется ли вероятность оформления депозита либо дата события. Для второго варианта потребуются другие данные.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент распознаёт неоднозначность «они» и «когда», задаёт уточняющий вопрос и не формирует окончательную конфигурацию без ответа. При обсуждении даты события указывает на отсутствие соответствующего таргета.
- **Допустимые альтернативы:** один или несколько кратких уточняющих вопросов; предварительное объяснение возможной бинарной постановки для `y` без запуска обучения.
- **Критические ошибки:** без уточнения трактовать запрос как готовую бинарную классификацию; утверждать, что `day` и `month` задают дату оформления депозита; выдумывать время согласия либо запускать модель для неподтверждённой задачи.
