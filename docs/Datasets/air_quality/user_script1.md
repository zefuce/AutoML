# AQ-01 - Восстановление отсутствующих измерений CO

**Датасет:** Air Quality (`AirQualityUCI.csv`)  
**Категория:** короткий  

## 1. Входные данные

**Запрос пользователя:**

> «Измеритель CO иногда молчит. Хочу восстанавливать CO(GT) по остальным датчикам в тот же час.»

**Вход для будущего теста:** исходный `AirQualityUCI.csv` вместе с приведённым выше текстом.

## 2. Ручной анализ запроса

Результат извлечения требований из текста:

```json
{
  "goal": {
    "value": "восстанавливать отсутствующие измерения CO по показаниям других датчиков",
    "status": "explicit"
  },
  "task_type": {
    "value": "regression",
    "status": "inferred"
  },
  "target": {
    "value": "CO(GT)",
    "status": "explicit"
  },
  "metric": {
    "value": null,
    "status": "unknown"
  },
  "constraints": {
    "training_time": {
      "value": null,
      "status": "unknown"
    }
  },
  "requirements": {
    "prediction_moment": {
      "value": "в тот же час, когда отсутствует измерение CO",
      "status": "explicit"
    },
    "feature_availability": {
      "value": "использовать показания других датчиков за тот же час",

```

Пользователь явно задаёт целевой показатель и момент восстановления, но не определяет метрику, время обучения и точный перечень доступных датчиков.

## 3. Ручное решение и конфигурация

- **Задача:** `label = "CO(GT)"`, `problem_type = "regression"`. Нужно оценивать числовую концентрацию CO в мг/м³ для часов без эталонного измерения.
- **Данные:** по EDA из 9 357 строк с измерениями в 1 683 отсутствует `CO(GT)` (`-200`); 7 674 строки имеют известный таргет. При чтении CSV учесть разделитель `;`, десятичную запятую, пустые строки и столбцы. Заменить `-200` на пропуски во всех числовых измерениях, не затрагивая допустимые отрицательные температуры. Обучаться только на строках с известным `CO(GT)`.
- **Признаки:** использовать показания сенсоров того же часа при подтверждённой доступности. Другие эталонные измерения (`NMHC(GT)`, `C6H6(GT)`, `NOx(GT)`, `NO2(GT)`) консервативно исключить, пока не подтверждено, что они доступны при отказе анализатора CO. Проверить пропуски в остальных датчиках.
- **Метрика:** `mean_absolute_error` - обоснованный начальный выбор в единицах концентрации, не указанный пользователем. Допустима `root_mean_squared_error` с обоснованием; качество оценивается только по строкам с известным таргетом.
- **Валидация:** независимую тестовую выборку выделять по времени из наблюдений с известным `CO(GT)`; внутренняя валидация AutoGluon - `auto`. Не смешивать будущие наблюдения с прошлым при внешней оценке и не считать восстановленные значения известными ответами.

**Кандидат конфигурации** (после проверки доступности других измерений):

```json
{
  "label": "CO(GT)",
  "problem_type": "regression",
  "eval_metric": "mean_absolute_error",
  "ignored_columns": ["NMHC(GT)", "C6H6(GT)", "NOx(GT)", "NO2(GT)"],
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

Обработка `-200`, очистка таблицы и внешнее временное разбиение выполняются до обучения, а не задаются параметрами `fit()`. `time_limit` назначает сервис; `ignored_columns` и `validation_procedure` обрабатываются обёрткой.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент определяет `CO(GT)` и регрессию; распознаёт `-200` как пропуск, не обучается на отсутствующем таргете, проверяет доступность датчиков того же часа и учитывает временной порядок при оценке.
- **Допустимые альтернативы:** `root_mean_squared_error` вместо `mean_absolute_error`; уточнение доступности других эталонных измерений, иное обоснованное исключение признаков. Порядок действий и формулировки агента не обязаны совпадать с эталоном.
- **Критические ошибки:** считать `-200` реальной концентрацией; обучаться на строках без известного `CO(GT)`; использовать недоступные при восстановлении признаки; оценивать качество на часах, где истинное значение CO отсутствует.
