# AQ-04 - Восстановление CO с ограничениями и отчётом

**Датасет:** Air Quality (`AirQualityUCI.csv`)  
**Категория:** длинный, ограничения  

## 1. Входные данные

**Запрос пользователя:**

> «У нас в лаборатории собираются ежечасные показания нескольких газовых сенсоров. Я хочу оценивать именно показания эталонного анализатора CO в те часы, когда этот прибор не выдал результат, но другие сенсоры работали. На обучение есть пять минут; запускать его можно только на CPU. Пожалуйста, подготовь базовую регрессионную задачу и после обучения покажи сравнение моделей и важность признаков, если это технически возможно. Отдельно учти специальные коды отсутствующих измерений — мне важно, чтобы модель не училась считать их настоящими концентрациями.»

**Вход для будущего теста:** исходный `AirQualityUCI.csv` вместе с приведённым выше текстом.

## 3. Ручное решение и конфигурация

- **Задача:** `label = "CO(GT)"`, `problem_type = "regression"`. По EDA в 1 683 из 9 357 часовых строк таргет отсутствует (`-200`), а 7 674 строк содержат известное измерение.
- **Данные и признаки:** преобразовать `-200` в пропуски во всех измерениях, удалить пустые строки и столбцы CSV; обучаться только на известном `CO(GT)`. Использовать доступные в тот же час сенсорные показатели, проверив их пропуски; другие эталонные `(GT)`-каналы исключить до подтверждения их доступности при восстановлении.
- **Метрика:** `mean_absolute_error` - обоснованный выбор для ошибки в мг/м³, не указанный пользователем. Допустима `root_mean_squared_error`. Для оценки применять временное разделение на прошлом и последующем периодах с известным таргетом.
- **Ограничения:** `time_limit = 300` секунд, `num_gpus = 0`. Пять минут относятся к обучению AutoGluon, а не гарантируют завершение всей подготовки и анализа результатов за это время.
- **Результаты:** `return_leaderboard = true` и `return_feature_importance = true` (если технически возможно) - настройки сервиса, а не параметры обучения. Расчёт важности может потребовать дополнительных вычислений и не доказывает причинного влияния признаков.

**Кандидат конфигурации** (после проверки доступности сенсоров):

```json
{
  "label": "CO(GT)",
  "problem_type": "regression",
  "eval_metric": "mean_absolute_error",
  "ignored_columns": ["NMHC(GT)", "C6H6(GT)", "NOx(GT)", "NO2(GT)"],
  "validation_procedure": "auto",
  "time_limit": 300,
  "num_gpus": 0,
  "presets": "medium_quality"
}
```

**Настройки сервиса:** `return_leaderboard = true`, `return_feature_importance = true` при технической возможности. Обработка пропусков и внешнее временное разбиение выполняются до обучения; `ignored_columns` и `validation_procedure` обрабатываются обёрткой.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент определяет `CO(GT)` и регрессию; обрабатывает `-200`, исключает неизвестный таргет из обучения; соблюдает `time_limit = 300`, `num_gpus = 0` и отдельно сохраняет запрос на сравнение моделей и важность признаков.
- **Допустимые альтернативы:** `root_mean_squared_error` вместо `mean_absolute_error`; уточнение доступности эталонных каналов; предупреждение о дополнительных затратах времени на важность признаков либо невозможности сформировать отчёт при заданных условиях.
- **Критические ошибки:** использовать `-200` как реальный таргет; включить недоступные датчики без проверки; потерять лимит обучения или запрет GPU; передать настройки отчёта как аргументы `fit()`; обещать причинную интерпретацию важности признаков.
