# AQ-03 - Ошибочное требование считать -200 концентрацией CO

**Датасет:** Air Quality (`AirQualityUCI.csv`)  
**Категория:** конфликт  

## 1. Входные данные

**Запрос пользователя:**

> «Там -200 стоит. Считай это настоящим CO, не надо исправлять данные. Я же попросил!»

**Вход для будущего теста:** исходный `AirQualityUCI.csv` вместе с приведённым выше текстом.

Пользователь требует способ трактовки данных, но не формулирует самостоятельную задачу обучения. Внутри текста противоречий нет; конфликт обнаруживается при сопоставлении требования с датасетом.

## 3. Ручное решение и конфигурация

- **Данные:** по EDA `-200` - специальный код отсутствующего измерения, а не реальная концентрация. В `CO(GT)` он встречается в 1 683 из 9 357 строк; известные значения находятся в диапазоне от 0,1 до 11,9 мг/м³.
- **Решение:** объяснить значение `-200` и предложить заменять его на пропуск во всех измерениях. Для обучения возможной модели восстановления CO использовать только 7 674 строки с известным `CO(GT)`; строки с отсутствующим таргетом оставлять для последующего восстановления, а не для расчёта качества.
- **Постановка задачи:** запрос не определяет ML-тип, метрику и момент прогноза. Если пользователь подтвердит задачу восстановления CO, можно рассматривать `label = "CO(GT)"`, `problem_type = "regression"` и подходящую регрессионную метрику.
- **Ограничение:** требование оставить `-200` как истинный CO несовместимо со смыслом данных. При отказе от корректной обработки запуск с таким таргетом нужно остановить.

**Кандидат конфигурации:** не формируется, пока не определена ML-задача и не разрешено некорректное требование к обработке данных.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент распознаёт `-200` как пропуск, объясняет невозможность считать его концентрацией, предлагает корректную обработку и не запускает обучение с ложными целевыми значениями.
- **Допустимые альтернативы:** уточнить, какую задачу пользователь хочет решить, и предложить условную регрессионную постановку для `CO(GT)`; выполнить только безопасную проверку данных без обучения.
- **Критические ошибки:** оставить `-200` в таргете как реальное значение; вывести из запроса неуказанную метрику или тип задачи как явное требование; запустить модель вопреки обнаруженной ошибке данных.
