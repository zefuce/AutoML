# AQ-02 - Неоднозначный прогноз загрязнения на следующий час

**Датасет:** Air Quality (`AirQualityUCI.csv`)  
**Категория:** разговорный  

## 1. Входные данные

**Запрос пользователя:**

> «ну чё, можно по этой табличке узнать загрязнение на СЛЕДУЮЩИЙ час? чтобы не смотреть в будущие датчики, понятное дело»

**Вход для будущего теста:** исходный `AirQualityUCI.csv` вместе с приведённым выше текстом.

Результат извлечения требований из текста:

```json
{
  "goal": {
    "value": "прогнозировать загрязнение воздуха на следующий час",
```

Неясно, какую характеристику загрязнения нужно предсказывать: концентрацию конкретного газа, общий показатель или категорию. Запрет использовать будущие показания не противоречит задаче.

## 3. Ручное решение и конфигурация

- **Задача:** сначала уточнить целевой показатель. В данных есть `CO(GT)` и другие концентрации `(GT)`, но пользователь не выбрал ни одну из них. Если требуется числовой прогноз `CO(GT)`, возможна регрессия после подготовки обучающей таблицы.
- **Признаки и таргет:** показания сенсоров относятся к своему часу. Для прогноза на следующий час нельзя использовать измерения этого будущего часа. Потребуются признаки из прошлого и корректно сдвинутый на один час таргет; исходный `CO(GT)` той же строки без преобразования не соответствует запросу.
- **Данные:** `-200` обозначает пропуски, а не концентрации; при создании сдвинутого таргета такие значения не становятся допустимыми метками. По EDA временная сетка почасовая и непрерывная.
- **Метрика и валидация:** после уточнения цели подобрать метрику, например MAE или RMSE для числовой концентрации. Проверять качество на более позднем периоде, не используя будущие данные при построении признаков.

**Кандидат конфигурации:** не формируется до уточнения целевого показателя и способа подготовки данных.

Сначала следует спросить, какой именно показатель загрязнения нужен. Если сервис не поддерживает построение лаговых признаков и сдвиг таргета, требуется заранее подготовленная таблица либо сообщение об ограничении; задача прогнозирования временного ряда не должна автоматически выдаваться за обычную регрессию по признакам того же часа.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент уточняет целевой показатель, сохраняет горизонт в один час, не использует будущие датчики и не формирует окончательную конфигурацию для неподтверждённой задачи. При выборе концентрации объясняет необходимость временной подготовки данных.
- **Допустимые альтернативы:** краткий вопрос о конкретном загрязнителе с предварительным предложением `CO(GT)`; запрос уже подготовленной таблицы с лагами, если такая подготовка недоступна сервису.
- **Критические ошибки:** без согласования выбрать `CO(GT)` как единственный таргет; обучать модель на показаниях прогнозируемого часа; выдавать восстановление значения того же часа за прогноз следующего; делать случайное разбиение и считать его проверкой будущего периода.
