# DIA-01 - Оценка качества на новых пациентах

**Датасет:** Diabetes 130-US Hospitals (`diabetic_data.csv`)  
**Категория:** валидация  

## 1. Входные данные

**Запрос пользователя:**

> «Мне важно понять, насколько модель сработает на новых пациентах, которых она никогда раньше не встречала. Результат нужен по всем трем вариантам повторной госпитализации.»

**Вход для будущего теста:** исходный `diabetic_data.csv` вместе с приведённым выше текстом; для трактовки кодов используется `IDS_mapping.csv`.

Пользователь требует оценку на новых пациентах и все три исхода, но не указывает момент прогнозирования, точное имя столбца или метрику.

## 3. Ручное решение и конфигурация

- **Задача:** По EDA целевой столбец `readmitted` содержит `NO` (53,91%), `>30` (34,93%) и `<30` (11,16%); выбрать `problem_type = "multiclass"`. Для внимания к менее частому классу допустима `f1_macro`, но пользователь метрику не задавал.
- **Валидация:** Для независимого теста разделять записи по `patient_nbr`: один пациент не должен присутствовать и в обучении, и в тесте. В датасете 71 518 уникальных пациентов, из них 16 773 имеют несколько госпитализаций. `validation_procedure = "auto"` не обеспечивает групповое разбиение; это отдельная логика сервиса. При внутреннем выборе модели также следует контролировать пересечения пациентов или явно указать ограничение.
- **Признаки:** Не использовать `encounter_id` и `patient_nbr` как предикторы. Обрабатывать `?` как пропуски, но не смешивать их со значением `None` в результатах анализов; медицинские коды проверять по `IDS_mapping.csv`.
- **Уточнение:** Согласовать момент прогноза - при поступлении или к выписке. До этого нельзя окончательно утверждать доступность `time_in_hospital`, `discharge_disposition_id`, сведений о лечении и других признаков.

**Кандидат конфигурации** (после согласования момента прогноза и доступных признаков):

```json
{
  "label": "readmitted",
  "problem_type": "multiclass",
  "eval_metric": "f1_macro",
  "ignored_columns": [
    "encounter_id",
    "patient_nbr"
  ],
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

Внешнее разделение по `patient_nbr` выполняет сервис до обучения; этот параметр отсутствует в JSON. `time_limit` задаётся сервисом, а `ignored_columns` и `validation_procedure` преобразуются обёрткой. Без решения о времени прогноза список исключаемых клинических признаков ещё не окончательный.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент определяет `readmitted`, `multiclass` и все три класса, сохраняет независимость пациентов в тесте, исключает идентификаторы из признаков, распознаёт специальные пропуски и уточняет момент прогноза.
- **Допустимые альтернативы:** другая обоснованная многоклассовая метрика; отдельные показатели по каждому классу; уточнение доступных признаков до окончательной конфигурации. Способ реализации разбиения может отличаться.
- **Критические ошибки:** случайный тест со смешением пациентов под видом оценки на новых пациентах; использование идентификаторов как количественных предикторов; применение данных лечения или выписки до их появления; подмена трёхклассовой задачи бинарной без согласия.
