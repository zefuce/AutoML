# DIA-02 - Прогноз повторной госпитализации в первые 30 дней

**Датасет:** Diabetes 130-US Hospitals (`diabetic_data.csv`)  
**Категория:** опечатки, разговорный  

## 1. Входные данные

**Запрос пользователя:**

> «ктo вернется в больничку за 30 дней после выписки? ну то есть выписали и он опять попал»

**Вход для будущего теста:** исходный `diabetic_data.csv` вместе с приведённым выше текстом; для трактовки кодов используется `IDS_mapping.csv`.

## 3. Ручное решение и конфигурация

- **Задача:** Исходный `readmitted` имеет три класса: `NO`, `>30`, `<30`. После согласования трактовки создать отдельный бинарный столбец `readmit_30d`: `1` для `<30`, `0` для `NO` и `>30`; положительный класс - `1`. Класс `<30` составляет 11,16% исходных наблюдений. Исходная трёхклассовая метка не является готовым бинарным таргетом.
- **Срок прогноза:** Уточнить, включается ли ровно 30-й день в требуемый исход: по имеющемуся обозначению `<30` эта граница не выделяется. Отдельно спросить, когда должна выдаваться оценка - например, при выписке или раньше. При прогнозе к выписке допустимы лишь признаки, уже известные к этому моменту.
- **Признаки:** После создания `readmit_30d` исключить исходный `readmitted` из признаков во избежание прямой утечки; также исключить идентификаторы `encounter_id` и `patient_nbr`. Учесть пропуски `?`, категорию `None` в анализах и особенности кодов выписки; проверить применимость исхода к пациентам с кодами смерти или хосписа.
- **Метрика и валидация:** `roc_auc` - допустимый начальный выбор для оценки риска, не указанный пользователем. Для оценки на новых пациентах использовать независимое разделение по `patient_nbr`; при внутреннем выборе модели также проверять групповые пересечения.

**Кандидат конфигурации** (после согласования границы 30 дней, момента прогноза и создания бинарного таргета):

```json
{
  "label": "readmit_30d",
  "problem_type": "binary",
  "positive_class": 1,
  "eval_metric": "roc_auc",
  "ignored_columns": [
    "readmitted",
    "encounter_id",
    "patient_nbr"
  ],
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

`readmit_30d` - новый столбец, который должен быть подготовлен до вызова AutoGluon; простая установка `problem_type = "binary"` для исходного `readmitted` некорректна. Групповое разбиение реализуется сервисом отдельно. `time_limit` задаётся сервисом, а `ignored_columns` и `validation_procedure` обрабатываются обёрткой.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент распознаёт 30-дневный бинарный исход, сопоставляет его с `<30`, учитывает необходимость преобразования таргета и исключения `readmitted` из признаков. Различает срок исхода и момент прогноза, проверяет доступность признаков и повторные записи пациентов.
- **Допустимые альтернативы:** другая обоснованная бинарная метрика; уточняющий вопрос о включении 30-го дня или о моменте выдачи прогноза до окончательного выбора конфигурации.
- **Критические ошибки:** задавать `binary` для исходного трёхклассового `readmitted` без преобразования; оставлять `readmitted` предиктором для производного таргета; использовать информацию, не известную в момент прогноза; смешивать одних пациентов в независимых train и test при оценке на новых пациентах.
