# Diabetes 130-US Hospitals - результат исследования

**Задача.** Исследовать признаки повторной госпитализации пациента с диабетом после выписки. Исходный таргет различает отсутствие повторной госпитализации и повторную госпитализацию до или после 30 дней. Момент прогноза необходимо уточнить.

**Данные.** UCI Diabetes 130-US Hospitals, `diabetic_data.csv`: 101 766 строк, 50 столбцов, из них 47 входных признаков, два идентификатора и таргет `readmitted`. Расшифровка отдельных кодов содержится в `IDS_mapping.csv`. Источник: [UCI Machine Learning Repository](https://archive.ics.uci.edu/dataset/296/diabetes+130-us+hospitals+for+years+1999-2008). Расчёты и графики приведены в `diabetes.ipynb`.

## 1. Первичный анализ

`readmitted` принимает три значения: `NO`, `>30`, `<30`. Исходная постановка - многоклассовая классификация. Некоторые целочисленные признаки являются категориями. `encounter_id` и `patient_nbr` - идентификаторы, а не количественные характеристики.

### Смысл признаков

| Признак или группа | Что содержит | На что обратить внимание |
|---|---|---|
| `encounter_id` | Идентификатор госпитализации | Уникальность, не использовать как обычный предиктор |
| `patient_nbr` | Идентификатор пациента | Несколько госпитализаций одного пациента |
| `race`, `gender`, `age`, `weight` | Демографические признаки | Пропуски, категории возраста, редкие группы |
| `admission_type_id`, `admission_source_id` | Тип и источник поступления | Категориальные коды, неопределённые значения |
| `discharge_disposition_id` | Статус и направление выписки | Доступность только при выписке, смерть и хоспис |
| `time_in_hospital` | Длительность пребывания | Доступность в момент прогноза |
| `num_lab_procedures`, `num_procedures` | Количество анализов и процедур | Распределения, информация о ходе госпитализации |
| `num_medications`, `number_diagnoses` | Количество лекарств и диагнозов | Диапазоны, связь с исходом |
| `number_outpatient`, `number_emergency`, `number_inpatient` | Предыдущие обращения | Большое количество нулей, связь с повторной госпитализацией |
| `payer_code`, `medical_specialty` | Код плательщика и специальность врача | Большое количество пропусков |
| `diag_1`, `diag_2`, `diag_3` | Коды диагнозов | Много категорий, не числовая шкала |
| `max_glu_serum`, `A1Cresult` | Результаты анализов | `None` означает, что анализ не выполнялся |
| Лекарственные признаки от `metformin` до `metformin-pioglitazone` | Сведения о назначении и изменении препаратов | Редкие и постоянные значения |
| `change`, `diabetesMed` | Изменение терапии и наличие диабетических препаратов | Доступность после лечения |
| `readmitted` | Повторная госпитализация | Целевая переменная, три класса |

## 2. Таргет

| Класс | Количество | Доля |
|---|---:|---:|
| `NO` | 54 864 | 53,91% |
| `>30` | 35 545 | 34,93% |
| `<30` | 11 357 | 11,16% |

Класс `<30` встречается реже остальных. Если задача пользователя ограничена повторной госпитализацией в первые 30 дней, требуется отдельно согласовать бинарную постановку.

## 3. Пропуски и специальные значения

В исходном CSV пропуски обозначены `?`. При чтении они распознаются как `NaN`. Строка `None` для результатов анализов остаётся отдельной категорией.

| Признак | `NaN`, шт. | Доля строк |
|---|---:|---:|
| `weight` | 98 569 | 96,86% |
| `medical_specialty` | 49 949 | 49,08% |
| `payer_code` | 40 256 | 39,56% |
| `race` | 2 273 | 2,23% |
| `diag_3` | 1 423 | 1,40% |
| `diag_2` | 358 | 0,35% |
| `diag_1` | 21 | 0,02% |

Всего 192 849 пропущенных входных значений (4,03% входных ячеек). Пропуски встречаются в 100 723 строках; полностью заполнены 1 043 строки.

При этом `A1Cresult = None` встречается 84 748 раз, `max_glu_serum = None` - 96 420 раз. В `gender` есть три записи `Unknown/Invalid`. Эти обозначения не объединяются с `NaN` без учёта смысла.

## 4. Дубликаты и повторные госпитализации

| Проверка | Результат |
|---|---:|
| Полные дубликаты строк | 0 |
| Повторы `encounter_id` | 0 |
| Уникальные пациенты | 71 518 |
| Пациенты с несколькими госпитализациями | 16 773 |
| Строки пациентов с повторными госпитализациями | 47 021 |

Госпитализации одного пациента представлены несколькими строками. При независимом случайном разбиении строк возможна утечка информации между обучением и проверкой. Для оценки на новых пациентах требуется разделение по `patient_nbr`.

## 5. Диапазоны, распределения и выбросы

Исследованы восемь количественных признаков. Отрицательных значений среди них нет. `time_in_hospital` находится в диапазоне от 1 до 14 дней. Для `number_outpatient`, `number_emergency` и `number_inpatient` характерно большое количество нулей.

Метод IQR применён к выбранным количественным признакам:

| Признак | Медиана | IQR-сигналы | Доля строк |
|---|---:|---:|---:|
| `time_in_hospital` | 4 | 2 252 | 2,21% |
| `num_lab_procedures` | 44 | 143 | 0,14% |
| `num_medications` | 15 | 2 557 | 2,51% |

Общий IQR для `number_outpatient`, `number_emergency` и `number_inpatient` не использовался из-за большого числа нулей.

## 6. Категориальные и лекарственные признаки

Для категорий вычислены размеры групп и доля исхода `<30`.

| Признак или группа | Наблюдение |
|---|---|
| `age` | `[70-80)`: 26 068 строк, 11,77% `<30`; `[80-90)`: 17 197 строк, 12,08% |
| `gender` | Три записи `Unknown/Invalid` |
| `A1Cresult` | `None`: 84 748 строк, 11,42% `<30`; `>8`: 8 216 строк, 9,87% |
| `max_glu_serum` | `None`: 96 420 строк, 11,09% `<30` |
| `change` | `No`: 10,59% `<30`; `Ch`: 11,82% |
| `diabetesMed` | `Yes`: 11,63% `<30`; `No`: 9,60% |

Среди 23 лекарственных признаков `examide` и `citoglipton` постоянны (`No` во всех строках). `insulin` имеет 54 383 значения, отличных от `No`, `metformin` - 19 988. У остальных лекарственных признаков размеры ненулевых групп различаются. Подробная таблица по каждому приведена в ноутбуке.

Коды `diag_1`, `diag_2`, `diag_3` имеют соответственно 716, 748 и 789 уникальных значений. В полях поступления и выписки также имеются специальные коды:

| Группа кодов | Количество строк |
|---|---:|
| `admission_type_id`: 5, 6, 8 | 10 396 |
| `admission_source_id`: 9, 15, 17, 20, 21 | 7 067 |
| `discharge_disposition_id`: 18, 25, 26 | 4 680 |

Согласно `IDS_mapping.csv`, эти коды обозначают отсутствие сведений, неотображённые значения и другие неопределённые категории. Они не являются формальными `NaN`.

## 7. Связь с повторной госпитализацией

Медиана `num_medications` составляет 14 для `NO`, 15 для `>30` и 16 для `<30`. Для истории стационарных обращений получены следующие результаты:

| `number_inpatient` | Строк | Доля `<30` |
|---|---:|---:|
| 0 | 67 630 | 8,44% |
| 1 | 19 521 | 12,92% |
| 2 | 7 566 | 17,43% |
| 3 и более | 7 049 | 25,66% |

Корреляция `number_inpatient` с индикатором ранней повторной госпитализации составляет около 0,165.

`pairplot` построен по выборке с одинаковым числом строк каждого класса - по 150. Такая визуализация позволяет сравнить распределения, но не отражает частоты классов в исходных данных.

## 8. Коды выписки и временная структура

| Категория по `IDS_mapping.csv` | Строк | Связь с `readmitted` |
|---|---:|---|
| Коды смерти | 1 652 | Только `NO` |
| Коды хосписа | 771 | У 86 записей значение отличается от `NO` |

`discharge_disposition_id` становится известен при выписке. Показатели лечения и обследований также зависят от момента прогноза. В CSV нет отдельной даты госпитализации или выписки, поэтому строгое временное разбиение по календарю не воспроизводится.

## 9. Итоги и эталон ожидаемых действий агента

| Что нужно решить | Обоснованный ориентир |
|---|---|
| Что предсказывать | `readmitted`, значения `NO`, `>30`, `<30` |
| Тип задачи | Многоклассовая классификация; при запросе о 30-дневном риске уточнить бинарную постановку |
| Дисбаланс | Учитывать 11,16% записей класса `<30` |
| Пропуски | Отличать `?` (`NaN`) от `None` в результатах анализов |
| Идентификаторы | Не использовать `encounter_id` как содержательный предиктор. Учитывать `patient_nbr` при разбиении |
| Валидация | Разделять пациентов между обучением и проверкой. Хронологическое разбиение по исходным полям недоступно |
| Категории | Расшифровывать коды через `IDS_mapping.csv`, не принимать их за числовую шкалу |
| Редкие и постоянные признаки | Проверить высокую долю пропусков `weight` и постоянные лекарственные поля |
| Риск утечки | Согласовать момент прогноза и доступность данных о лечении, анализах и выписке |
| Метрика | Выбирать с учётом различий классов и цены ошибок |

## Как воспроизвести

Открыть `diabetes.ipynb` в VS Code или Jupyter, установить `pandas`, `matplotlib`, `seaborn` и выполнить ячейки сверху вниз. Рядом с ноутбуком должны лежать исходные `diabetic_data.csv` и `IDS_mapping.csv`.
