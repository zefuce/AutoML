# Т-Банк: Коммуникации в Городе - результат исследования

Задача исследования - изучить коммуникации с клиентами сервисов «Города» и определить особенности данных, влияющие на конфигурацию AutoML для прогноза заказов. Данные содержат шесть столбцов количества заказов по сервисам; единая целевая переменная и горизонт прогноза не заданы.

Источник: DANO, предоставленные `Коммуникации в Городе.pdf` и `коммуникации по Городу.csv`. Все показатели и графики рассчитаны в `EDA_tbank_gorod_communications.ipynb`.

Для воспроизведения необходим файл [коммуникации по Городу.csv](https://drive.google.com/file/d/1JmuG4M9BoHz6iKCFQDHNGUiBdJCjwM3j/view?usp=drive_link), размещённый рядом с ноутбуком.

## 6. Связь коммуникаций с заказами

Во всех строках есть хотя бы один клик по какому-либо сервису. Вместе с тем заказ отдельного сервиса может встречаться без клика по этому же сервису в данной строке.

| Сервис | Заказов без клика этого сервиса, строк | Доля заказов при отсутствии клика, % | Доля заказов при наличии клика, % |
|---|---:|---:|---:|
| Развлечения | 372 | 0,41 | 2,41 |
| Супермаркеты | 1 613 | 1,80 | 2,84 |
| Транспорт | 2 735 | 3,77 | 6,87 |
| Шопинг | 439 | 0,46 | 1,34 |
| Отели | 321 | 0,30 | 1,03 |

Доли рассчитаны среди строк без клика или с кликом соответствующего сервиса. Наблюдаемая связь не является доказательством, что коммуникация привела к заказу: в описании указано, что покупка может произойти позднее коммуникации, а способ отбора пользователей и назначения контактов неизвестен.

Для иллюстративной хронологической проверки использована граница `2025-09-01`.

|---|---:|---:|
| Строк | 91 888 | 26 301 |
| Уникальных клиентов | 8 332 | 7 252 |
| Строк с заказами | 8 967 | 2 023 |

В обеих частях встречаются 7 245 общих клиентов. Для прогноза будущих событий известных клиентов их повторяемость может быть допустима при использовании только прошлой информации; для оценки работы на новых клиентах требуется разбиение по `id`. Такая иллюстративная граница не заменяет полноценной валидации до определения горизонта целевого события.

## 9. Постановка цели и ограничения доступности признаков

В зависимости от задачи возможна классификация факта заказа или регрессия его количества для выбранного сервиса. Но в CSV не указаны момент принятия решения и горизонт, в пределах которого следует оценивать результат.

При прогнозе до коммуникации нельзя использовать показы, клики и заказы, появившиеся после этого момента. Таблица содержит только `business_dt`, без времени каждого показа, клика и заказа. Поэтому для событий одного дня неизвестен точный порядок их возникновения.

Нерегулярные записи клиентов не позволяют без дополнительных условий формировать корректные отрицательные метки на следующие 7 или 30 дней: отсутствующий день не тождествен отсутствию покупки. Также недостаточно информации для причинной оценки эффективности коммуникаций.

## 10. Выводы для настройки AutoML

1. Уточнять целевой сервис, тип исхода и горизонт: шесть счётчиков `orders_amt_*` не задают единственной цели.
2. Для факта заказа рассматривать бинарную классификацию, для количества - регрессию. Доля положительных наблюдений существенно зависит от сервиса.
3. Не приравнивать отсутствующие даты клиента к нулевым заказам; при построении будущего таргета учитывать полноту наблюдений.
4. Исключать из признаков будущие и одновременные события, чья доступность на момент прогноза не доказана.
5. Для будущих периодов рассматривать хронологическую валидацию; для новых клиентов - отдельную групповую проверку.
6. Нормализовать написания платформы, исследовать несогласованные счётчики показов и кликов, не исправляя их без оснований.
7. Не выдавать связь кликов и заказов за причинный эффект коммуникации.

## Итог

Т-Банк «Коммуникации в Городе» позволяет исследовать конфигурацию AutoML при неоднозначном таргете, редких заказах в отдельных сервисах, повторных клиентах, нерегулярных датах и ограничениях доступности признаков. Ключевое ограничение не устраняется автоматической очисткой: для обучения прогноза на будущий горизонт необходимо подтвердить полноту истории и временной смысл счётчиков.
