# IEEE-CIS Fraud Detection - результат исследования

Задача исследования - определить особенности данных финансовых транзакций и сложности настройки AutoML для выявления мошеннических операций. Целевая переменная `isFraud`: 1 - мошенничество, 0 - обычная операция.

Данные: [IEEE-CIS Fraud Detection (Kaggle)](https://www.kaggle.com/competitions/ieee-fraud-detection/data), опубликованы на основе данных Vesta Corporation. Исходный файл [ieee-fraud-detection.zip](https://drive.google.com/file/d/1qRvDwZR54C_vmY2f0UfQMf_aEYStVppc/view?usp=drive_link). Расчёты и графики приводятся в `EDA_ieee_fraud_detection.ipynb`.

## 1. Первичный анализ

| Файл | Строк | Столбцов | Назначение |
|---|---:|---:|---|
| `train_transaction.csv` | 590 540 | 394 | Транзакции с таргетом |
| `train_identity.csv` | 144 233 | 41 | Дополнительные данные по части транзакций |
| `test_transaction.csv` | 506 691 | 393 | Транзакции без таргета |
| `test_identity.csv` | 141 907 | 41 | Дополнительные признаки для части теста |
| `sample_submission.csv` | - | 2 | Шаблон предсказаний, в EDA не используется |

Основная таблица содержит 393 других столбца (включая идентификатор и относительное время) и `isFraud`. Дополнительные таблицы связываются с ней по `TransactionID`. Пропуски и наличие постоянных значений проверяются по всем столбцам; распределения подробно рассматриваются для представителей основных групп признаков.

### Смысл основных групп признаков

| Поля | Содержание | На что обратить внимание |
|---|---|---|
| `TransactionID` | Идентификатор транзакции | Ключ соединения, не должен бездумно использоваться как обычный признак |
| `TransactionDT` | Относительное время транзакции в секундах | Временная валидация; абсолютная календарная дата не раскрыта |
| `TransactionAmt` | Сумма операции | Сильно асимметричное распределение, крупные платежи |
| `ProductCD` | Код типа продукта | Различная распространённость мошенничества по категориям |
| `card*`, `addr*`, `dist*`, `P_emaildomain`, `R_emaildomain` | Закодированные сведения об операции и сторонах платежа | Пропуски, кардинальность, ограничения интерпретации |
| `C*`, `D*`, `M*`, `V*` | Анонимизированные группы признаков | Высокая размерность, разреженность, неопределённость момента получения |
| `id_*`, `DeviceType`, `DeviceInfo` | Дополнительные сведения `identity` | Доступны только для части операций; отличие схем train/test |

## 3. Пропуски и покрытие identity

| Показатель | Результат |
|---|---:|
| Столбцов с более чем 50% пропусков в `train_transaction` | 174 |
| Столбцов с более чем 90% пропусков | 2 |
| `dist2`: доля пропусков | 93,63% |
| `D7`: доля пропусков | 93,41% |
| `R_emaildomain`: доля пропусков | 76,75% |
| `dist1`: доля пропусков | 59,65% |
| `D4`: доля пропусков | 28,60% |
| `M1`: доля пропусков | 45,91% |
| Транзакций с соответствующей записью `identity` | 144 233 (24,42%) |

Средняя доля пропусков по группе `D*` составляет 58,15%, по `V*` - 43,04%, по `C*` - 0%. Это среднее по столбцам соответствующей группы, а не доля строк, содержащих хотя бы один пропуск. В исходной таблице не выявлено полностью пустых или постоянных столбцов.

| Группа по наличию `identity` | Количество операций | Доля `isFraud = 1` |
|---|---:|---:|
| Есть запись в `identity` | 144 233 | 7,85% |
| Нет записи в `identity` | 446 307 | 2,09% |

Наличие записи `identity` тесно связано с типом продукта:

| `ProductCD` | Доля операций с `identity` |
|---|---:|
| W | 0,00% |
| C | 90,77% |
| H | 99,65% |
| R | 99,60% |
| S | 99,63% |

Дополнительная проверка пропусков по классам показала, что `M1` отсутствует у 45,06% обычных операций и 69,31% мошеннических; для `V200` эти значения составляют 77,41% и 46,43%. Различия не доказывают причинной связи между отсутствием признака и мошенничеством.

У части признаков пропуски связаны с типом продукта: `M1` отсутствует во всех транзакциях типов `C`, `H`, `R`, `S`, а `V200` отсутствует во всех транзакциях типа `W`. Следовательно, удаление строк или столбцов по порогу пропусков может повлиять на состав продуктов.

Поэтому различие в долях мошенничества между операциями с `identity` и без неё нельзя интерпретировать отдельно от состава типов операций. Удаление строк без `identity` исключит весь тип `W` и значительно изменит исходную задачу.

## 4. Распределения, категории и выбросы

Сумма операции имеет длинный правый хвост: медиана 68,77, а максимум 31 937,39. Крупные значения сами по себе не означают ошибку; их нужно рассматривать по контексту и при необходимости проверять отдельно.

| `ProductCD` | Транзакций | Доля мошенничества |
|---|---:|---:|
| W | 439 670 | 2,04% |
| C | 68 519 | 11,69% |
| R | 37 699 | 3,78% |
| H | 33 024 | 4,77% |
| S | 11 628 | 5,90% |

Категории различаются по частоте мошенничества. `card1` высококардинален. `P_emaildomain` содержит 59 различных значений, `R_emaildomain` - 60. Значения типа продукта и платёжной системы связаны с разной частотой мошенничества, но не устанавливают причины таких различий.

Медианная сумма обычной операции составляет 68,50, мошеннической - 75,00. Средние суммы равны 134,51 и 149,24 соответственно. Различия распределений не позволяют сами по себе определять мошенничество.

Для `card1` обнаружено 3 444 значения, встречающихся только в одной операции. Сто наиболее частых значений охватывают 47,43% операций с известным `card1`. Это подтверждает неравномерную частоту категорий.

У `TransactionAmt` не обнаружено нулевых и отрицательных значений. При проверке сочетания `TransactionDT`, `TransactionAmt`, `ProductCD`, `card1`, `card4` обнаружено 64 повтора. Это повторы выбранных полей, а не доказанные дубликаты полных записей. Удалять их автоматически не следует.

## 5. Временная структура

`TransactionDT` - относительное время в секундах от скрытого начала. Доступные train-транзакции охватывают приблизительно 182 дня. Между концом train и началом test около 30 дней.

| Последовательный 30-дневный интервал | Число операций | Доля мошенничества |
|---|---:|---:|
| 0 | 130 968 | 2,48% |
| 1 | 89 838 | 4,04% |
| 2 | 91 768 | 4,03% |
| 3 | 98 027 | 3,93% |
| 4 | 85 303 | 3,47% |
| 5 | 86 525 | 3,40% |
| 6 (неполный) | 8 111 | 4,18% |

Интервалы условные, не календарные месяцы. Частота мошенничества меняется во времени. Доля операций с `identity` составляет 43,6% в первом интервале и около 17,7-21,1% в последующих. Для проверки прогноза будущих операций нужен хронологический отложенный период. Конкурсный test без `isFraud` не подходит для локального расчёта качества модели.

## 6. Различия train/test и согласованность схем

`test_transaction` совпадает по названиям столбцов с обучающей таблицей за исключением `isFraud`. В `test_identity.csv` признаки обозначены как `id-01`, `id-02`, ..., а в `train_identity.csv` - `id_01`, `id_02`, ... . Перед объединением и применением модели названия необходимо нормализовать.

| Признак | Пропуски train | Пропуски test |
|---|---:|---:|
| `D4` | 28,60% | 15,17% |
| `M1` | 45,91% | 34,86% |
| `M9` | 58,63% | 46,38% |
| `V200` | 76,32% | 73,09% |
| `R_emaildomain` | 76,75% | 73,18% |
| `dist1` | 59,65% | 57,47% |
| `dist2` | 93,63% | 92,81% |

Для `TransactionAmt` медиана в train составляет 68,77, в test - 67,95; 95-й процентиль - 445,00 и 439,70 соответственно. В данном случае существенного изменения этих двух характеристик суммы не обнаружено.

Отличия долей пропусков и структуры категорий указывают на изменение наблюдаемых распределений. В ноутбуке дополнительно сравниваются выбранные признаки групп `D`, `M`, `V`, а также пропуски в обеих таблицах `identity`. Без дополнительных сведений нельзя утверждать, что причины этих изменений установлены. Пересечений `TransactionID` между train и test не выявлено.

## 7. Связи признаков с таргетом

Среди выбранных числовых признаков заметна корреляция `V200` с `isFraud` (r около 0,319). Значение `V200` присутствует у 139 819 транзакций. Доля мошенничества при наличии `V200` составляет 7,92%, при отсутствии - 2,13%. Поскольку значение рассчитано на подмножестве операций и происхождение поля скрыто, корреляция не доказывает утечку. Проверка доступности значения на момент операции требует дополнительных сведений.

## 8. Риски утечек и ограничения интерпретации

- Подтверждённые особенности: различия схем identity; пропуски с неравномерным покрытием; высокий дисбаланс; различия train/test; временная структура.
- Потенциальные риски: использование признаков, рассчитанных после операции или после антифрод-решения, может создать утечку. Из-за анонимизации полей это нельзя проверить только по корреляциям.
- Ограничения данных: время доступности части анонимизированных признаков и стоимость FP/FN. При необходимости агент должен запросить уточнение или предупредить об ограничении.

## 9. Ожидаемые действия AutoML-агента

1. Сопоставить прикладную задачу с `isFraud` и `binary`; положительный класс - `1`.
2. Учитывать дисбаланс при выборе метрик, не выбирать основную метрику безотносительно бизнес-цели; для первичного эксперимента возможен `roc_auc`, но он не задаёт стоимость ошибок и порог решения.
3. Не удалять по умолчанию записи без `identity` и все сильно разреженные признаки.
4. Проверить уникальность ключей `TransactionID` и согласованность имён колонок при соединении таблиц.
5. Выделять независимую оценочную часть train хронологически при проверке будущих операций; не использовать неразмеченный конкурсный test для оценки качества.
6. Отличать доказанные ошибки схемы от гипотез об утечках и сообщать о невозможности доказать доступность анонимизированных полей без контекста.
7. Учитывать особенности многочисленных обезличенных признаков и временные изменения полноты данных.

IEEE-CIS Fraud Detection нужен для исследования сложных условий конфигурирования AutoML на реальных транзакционных данных. Набор полезен для проверки редких классов, неполных дополнительных данных, временной валидации, высокой размерности и различий схем.
