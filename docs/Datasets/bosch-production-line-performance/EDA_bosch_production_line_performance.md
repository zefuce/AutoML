# Bosch Production Line Performance - результат исследования

Задача исследования - изучить производственные измерения и определить особенности данных, которые необходимо учитывать при настройке AutoML для выявления дефектов. Целевая переменная `Response`: 1 - дефект, 0 - нормальная деталь.

Данные: [Bosch Production Line Performance (Kaggle)](https://www.kaggle.com/competitions/bosch-production-line-performance/data). Расчёты и графики приводятся в `EDA_bosch_production_line_performance.ipynb`.

## 1. Первичный анализ

| Файл | Строк | Столбцов | Назначение |
|---|---:|---:|---|
| `train_numeric.csv` | 1 183 747 | 970 | Числовые измерения и `Response` |
| `train_categorical.csv` | 1 183 747 | 2141 | Категориальные измерения |
| `train_date.csv` | 1 183 747 | 1157 | Время производственных измерений |
| `test_numeric.csv` | 1 183 748 | 969 | Числовые измерения без таргета |
| `test_categorical.csv` | 1 183 748 | 2141 | Категориальные признаки теста |
| `test_date.csv` | 1 183 748 | 1157 | Временные признаки теста |

Таблицы связываются по `Id`. Таргет присутствует только в `train_numeric.csv`. В исходной структуре train и test названия признаков совпадают, за исключением `Response` в обучающей таблице. В основной числовой таблице не обнаружены дубликаты `Id`; пересечений `Id` между train и test также нет.

### Основные группы признаков

| Группа | Содержание | Ограничения |
|---|---|---|
| `L*_S*_F*` | Числовые или категориальные измерения станций | Высокая разреженность, неизвестная доступность к моменту прогноза |
| `L*_S*_D*` | Относительное время измерения | Требуется учитывать порядок производственных этапов |
| `Id` | Идентификатор детали | Используется для согласования таблиц |
| `Response` | Наличие дефекта | Целевая переменная бинарной классификации |

Доля дефектных деталей очень мала. По одной accuracy нельзя судить о способности модели обнаруживать редкий брак. Выбор метрики должен учитывать приоритет ошибок и прикладную задачу; данные не содержат стоимости ошибок.

## 3. Пропуски и структура признаков

| Группа | Средняя доля пропусков | Более 50% | Более 90% | Полностью пустые |
|---|---:|---:|---:|---:|
| Числовые | 80,92% | 812 | 634 | 0 |
| Категориальные | 97,28% | 2077 | 2010 | 163 |
| Временные | 82,17% | 986 | 762 | 0 |

Средняя доля пропусков рассчитана по столбцам каждой таблицы, включая `Id` и, для числовой группы, `Response`. Это не доля строк с хотя бы одним пропуском.

В числовой группе особенно разрежены признаки станции `L1_S25`: например, `L1_S25_F2181` отсутствует в 99,89% строк. В категориальной таблице обнаружены полностью пустые признаки. Отсутствие измерения может быть связано с прохождением конкретной станции и не обязательно означает ошибку сбора данных. Удаление строк или признаков по единому порогу пропусков может изменить состав производственных маршрутов.

Для каждой детали рассчитаны первое и последнее известное время измерения. Временная шкала относительная, а не календарная. Число деталей без временных измерений: 582. Медианная разность между последним и первым измерением равна 3,70 в единицах исходной шкалы.

Частота дефектов меняется между временными группами. При проверке качества прогнозов для более поздних деталей требуется учитывать временной порядок. Разбиение по первому измерению является приближением; фактические календарные даты из исходных файлов не устанавливаются.

## 7. Различия train/test и согласованность схем

В числовой таблице train имеется 970 столбцов, в test - 969, разница связана с `Response`. Для категориальной и временной таблиц число и названия столбцов совпадают. В ноутбуке отдельно сравниваются доли пропусков признаков с различной заполненностью между train и test.

Сравнение схем не исключает изменения распределений, поэтому их заполненность и значения следует проверять независимо. Конкурсный test не содержит правильных ответов для самостоятельного расчёта метрики.

## 8. Связи признаков с таргетом

Для выбранных числовых признаков вычисляются корреляции с `Response` на исследуемой части данных. Отдельно рассматривается наличие измерений на станциях. Так как классы существенно несбалансированы, результаты сравнений на небольшом подмножестве следует трактовать осторожно.

Корреляция, заполненность и положение станции в маршруте не позволяют установить причину возникновения дефекта. Доступность измерения на момент прогнозирования требует дополнительной предметной информации.

## 9. Риски утечек и ограничения интерпретации

- Подтверждённые свойства: редкий положительный класс, большое количество разреженных признаков, полностью пустые категориальные столбцы, временная неоднородность, многочисленные производственные станции.
- Потенциальные риски: часть измерений может появляться после этапа, на котором необходимо прогнозировать дефект. Сами данные не позволяют доказать, что такие признаки создают утечку.
- Ограничения: значение анонимизированных измерений и точный момент принятия решения о браке неизвестны. Для однозначного вывода необходимы сведения о производственном процессе.

## 10. Ожидаемые действия AutoML-агента

1. Определить `Response` и бинарную классификацию; положительный класс - `1`.
2. Учитывать редкие дефекты при выборе метрики и не ограничиваться общей точностью.
3. Анализировать структуру пропусков и не удалять разреженные признаки без проверки производственного контекста.
4. Проверять уникальность `Id` и согласованность трёх групп признаков при объединении.
5. Учитывать изменение частоты брака во времени при выборе внешнего разбиения.
6. Проверять доступность признаков к моменту прогноза и не объявлять неподтверждённые утечки доказанными.
7. Учитывать многочисленные признаки и отличия train/test при построении конфигурации.

## Итог

Bosch Production Line Performance позволяет исследовать задачи настройки AutoML при редком производственном браке, высокой размерности и структурной разреженности, а также при временной неоднородности данных. Проверки охватывают как статистические свойства таблиц, так и риски некорректного использования измерений производственных этапов.
