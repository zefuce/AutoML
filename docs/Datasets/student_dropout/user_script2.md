# SD-02 - Прогноз после первого семестра

**Датасет:** Predict Students' Dropout and Academic Success (`data.csv`)  
**Категория:** короткий  

## 1. Входные данные

**Запрос пользователя:**

> «Предсказание судьбы студентов по итогам 1 семестра, данные второго пока использовать нельзя.»

**Вход для будущего теста:** исходный `data.csv` вместе с приведённым выше текстом.

## 2. Ручной анализ запроса

Результат извлечения требований из текста:

```json
{
  "goal": {
    "value": "предсказывать дальнейшую академическую судьбу студентов на основе итогов первого семестра",
    "status": "explicit"
  },
  "task_type": {
    "value": null,
    "status": "ambiguous"
  },
  "target": {
    "value": "дальнейшая академическая судьба; конкретные исходы не перечислены",
    "status": "ambiguous"
  },
  "metric": {
    "value": null,
    "status": "unknown"
  },
  "constraints": {
    "training_time": {
      "value": null,
      "status": "unknown"
    }
  },
  "requirements": {
    "prediction_moment": {
      "value": "по завершении первого семестра",
      "status": "explicit"
    },
    "feature_availability": {
      "value": "данные второго семестра использовать нельзя",
      "status": "explicit"
    }
  },
  "conflicts": []
}
```

Пользователь явно определяет момент прогноза и запрещает данные второго семестра, но слово «судьба» не уточняет классы исходов. Тип задачи и таргет требуют сопоставления с датасетом и подтверждения.

## 3. Ручное решение и конфигурация

- **Задача:** В датасете `Target` содержит `Dropout`, `Enrolled` и `Graduate`, поэтому можно предложить трёхклассовый прогноз (`multiclass`). Уточнить, устраивают ли пользователя именно эти исходы; без согласования не считать их прямо названными в запросе.
- **Признаки:** Все шесть `Curricular units 2nd sem (...)` исключить как недоступные после первого семестра. Показатели `Curricular units 1st sem (...)` допустимы лишь в том объёме, в котором они реально известны к моменту прогноза. Также проверить дату определения `Debtor`, `Tuition fees up to date`, `Scholarship holder` и макропоказателей.
- **Метрика:** После подтверждения трёхклассовой постановки допустима `f1_macro` с учётом распределения классов (реже всего `Enrolled`, 17,95%). В запросе конкретной метрики нет.
- **Валидация:** Для первоначальной оценки возможно независимое стратифицированное случайное разбиение. Без временных меток и идентификаторов оно не подтверждает качество на следующих наборах студентов; внутренняя валидация AutoGluon - `auto`.

**Кандидат конфигурации** (если подтверждён трёхклассовый прогноз по `Target` и доступность признаков первого семестра):

```json
{
  "label": "Target",
  "problem_type": "multiclass",
  "eval_metric": "f1_macro",
  "ignored_columns": [
    "Curricular units 2nd sem (credited)",
    "Curricular units 2nd sem (enrolled)",
    "Curricular units 2nd sem (evaluations)",
    "Curricular units 2nd sem (approved)",
    "Curricular units 2nd sem (grade)",
    "Curricular units 2nd sem (without evaluations)"
  ],
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

В таблице нет формальных `NaN`; нулевые оценки нельзя автоматически считать пропусками. `time_limit` назначает сервис. `ignored_columns` и `validation_procedure` требуют преобразования обёрткой, а проверка доступности финансовых и макроэкономических признаков должна предшествовать запуску.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент распознаёт момент после первого семестра, исключает все поля второго семестра, допускает лишь уже известные данные первого, сопоставляет возможный таргет с `Target` и уточняет смысл «судьбы» до окончательного выбора классов.
- **Допустимые альтернативы:** предложить бинарную постановку после уточнения, если пользователь интересуется конкретным исходом; подобрать другую метрику, соответствующую согласованной задаче.
- **Критические ошибки:** использовать признаки второго семестра; объявить трёхклассовую постановку прямо указанной пользователем; запускать окончательное обучение с неопределённым целевым событием или включать неизвестные на момент прогноза статусы.
