# SD-03 - Неоднозначный интерес к отчисленным студентам

**Датасет:** Predict Students' Dropout and Academic Success (`data.csv`)  
**Категория:** неоднозначный  

## 1. Входные данные

**Запрос пользователя:**

> «Интересуют только отчисленные.»

**Вход для будущего теста:** исходный `data.csv` вместе с приведённым выше текстом.

## 3. Ручное решение и конфигурация

- **Данные:** В `Target` три класса: `Dropout` (1 421 студент), `Enrolled` (794) и `Graduate` (2 209). Само упоминание отчисленных не означает, что пользователь потребовал бинарную классификацию.
- **Уточнение:** Спросить, требуется ли предсказывать отчисление, анализировать уже отчисленных или оценивать все три исхода с особым вниманием к `Dropout`. Для прогноза дополнительно согласовать момент применения и горизонт, поскольку список доступных признаков зависит от семестра.
- **Возможные ML-постановки:** Если нужна бинарная модель `Dropout` против остальных, на этапе подготовки данных создать новый столбец, например `is_dropout` (`1` для `Dropout`, `0` для остальных), и исключить исходный `Target` из предикторов, чтобы избежать прямой утечки. Важно уточнить, приемлемо ли объединять ещё обучающихся (`Enrolled`) с выпускниками (`Graduate`) в отрицательный класс: это «не отчислен по имеющейся разметке», а не доказательство отсутствия отчисления в будущем. Если нужны все три исхода, сохранить `Target` и `multiclass`, отдельно оценивая качество на `Dropout`.
- **Метрика и проверка:** Определять после выбора задачи; в бинарном варианте может быть важен `recall` для класса `1`, но пользователь пока не задавал приоритет ошибок. Данные не содержат явных дат и ID студентов для теста на новых учебных наборах.

**Кандидат конфигурации:** не формируется до уточнения требуемого действия, целевого исхода и момента прогноза.

Если пользователь подтвердит бинарный прогноз, подготовка нового таргета выполняется отдельно от настройки AutoGluon. Упоминание `Dropout` ещё не разрешает автоматически перекодировать остальные классы.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент распознаёт интерес к `Dropout`, предлагает уточнить задачу и не выбирает бинарную или многоклассовую модель без обоснования. При бинарном варианте предусматривает создание нового таргета и исключение исходного `Target` из признаков.
- **Допустимые альтернативы:** сначала уточнить, нужен ли вообще прогноз; предложить трёхклассовую модель с оценкой качества `Dropout` или бинарную модель после согласования, как трактовать `Enrolled`.
- **Критические ошибки:** без уточнения запустить модель; принять `Enrolled` за гарантированно не отчисляющихся в будущем; оставить `Target` в признаках после создания `is_dropout`; выдумать конкретный момент прогноза или метрику.
