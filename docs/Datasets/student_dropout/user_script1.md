# SD-01 - Ранний прогноз академического статуса при поступлении

**Датасет:** Predict Students' Dropout and Academic Success (`data.csv`)  
**Категория:** длинный  

## 1. Входные данные

**Запрос пользователя:**

> «В университете у нас каждый год большой набор. Сейчас обсуждаем, можно ли уже при поступлении оценивать будущую траекторию студента: отчислится ли он, еще будет учиться или в итоге окончит программу. Таблицу с результатами за разные годы я приложил. В ней есть сведения об успеваемости по семестрам, но для нового абитуриента они пока неизвестны. Нам нужен именно ранний прогноз, а не объяснение результатов после двух лет учебы. Еще хотелось бы не забывать про менее многочисленные исходы, иначе модель станет предсказывать только самый частый класс.»

**Вход для будущего теста:** исходный `data.csv` вместе с приведённым выше текстом.

## 3. Ручное решение и конфигурация

- **Задача:** По EDA целевой столбец `Target` содержит `Dropout` (32,12%), `Enrolled` (17,95%) и `Graduate` (49,93%); выбрать `problem_type = "multiclass"`. Более редкий класс `Enrolled` требует внимания при оценке.
- **Признаки:** При поступлении недоступны все шесть `Curricular units 1st sem (...)` и все шесть `Curricular units 2nd sem (...)`; их следует исключить. Проверить, были ли к моменту поступления известны `Debtor`, `Tuition fees up to date`, `Scholarship holder` и макроэкономические показатели. Коды учебных программ и прочих категорий не трактовать как непрерывные величины.
- **Метрика:** `f1_macro` - обоснованный начальный выбор для трёх классов с различными долями, но пользователь её не указывал. Полезно оценивать качество отдельно по классам.
- **Валидация:** Возможен независимый стратифицированный случайный тест как предварительная оценка; внутренняя валидация AutoGluon - `auto`. В исходном CSV нет явных дат и идентификаторов студентов, поэтому такую проверку нельзя называть тестом на будущем наборе студентов.

**Кандидат конфигурации** (после подтверждения доступности остальных признаков при поступлении):

```json
{
  "label": "Target",
  "problem_type": "multiclass",
  "eval_metric": "f1_macro",
  "ignored_columns": [
    "Curricular units 1st sem (credited)",
    "Curricular units 1st sem (enrolled)",
    "Curricular units 1st sem (evaluations)",
    "Curricular units 1st sem (approved)",
    "Curricular units 1st sem (grade)",
    "Curricular units 1st sem (without evaluations)",
    "Curricular units 2nd sem (credited)",
    "Curricular units 2nd sem (enrolled)",
    "Curricular units 2nd sem (evaluations)",
    "Curricular units 2nd sem (approved)",
    "Curricular units 2nd sem (grade)",
    "Curricular units 2nd sem (without evaluations)"
  ],
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

Формальных `NaN` по EDA нет: нулевые оценки и показатели дисциплин нельзя автоматически превращать в пропуски. Файл разделён `;`, а имя `Daytime/evening attendance` в оригинале содержит завершающую табуляцию. `time_limit` подставляет сервис; `ignored_columns` и `validation_procedure` обрабатываются обёрткой.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент распознаёт `Target` и три класса, исключает все признаки обоих семестров, проверяет доступность финансовых и иных сведений при поступлении, учитывает дисбаланс и не выдаёт случайное разбиение за проверку на новом учебном наборе.
- **Допустимые альтернативы:** другая обоснованная многоклассовая метрика; уточнение происхождения спорных признаков до окончательной конфигурации; дополнительные оценки качества по отдельным классам.
- **Критические ошибки:** использовать результаты первого или второго семестра для прогноза при поступлении; свести исходную задачу к бинарной без запроса; приписать пользователю `f1_macro`; заявить, что проверка на будущих наборах подтверждена датами, которых нет в таблице.
