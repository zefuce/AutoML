# SD-04 - Трёхклассовый прогноз после второго семестра с ограничениями

**Датасет:** Predict Students' Dropout and Academic Success (`data.csv`)  
**Категория:** явный, ограничения  

## 1. Входные данные

**Запрос пользователя:**

> «Используй `Target` как многоклассовый таргет. Метрика `f1_macro`, лимит обучения 600 секунд, GPU не использовать. Прогноз строится после завершения второго семестра; покажи сравнение обученных моделей.»

**Вход для будущего теста:** исходный `data.csv` вместе с приведённым выше текстом.

## 3. Ручное решение и конфигурация

- **Задача:** `label = "Target"`, `problem_type = "multiclass"`, `eval_metric = "f1_macro"`. По EDA классы `Graduate` (49,93%), `Dropout` (32,12%) и `Enrolled` (17,95%); выбранная метрика учитывает каждый класс при усреднении.
- **Признаки:** После завершения второго семестра можно рассматривать показатели обоих семестров, только если они действительно известны на момент прогноза. Проверить актуальность финансовых статусов и макропоказателей; не использовать значения, отражающие события после второго семестра. Нулевые семестровые оценки, связанные с отсутствием одобренных дисциплин, не объявлять пропусками автоматически. Категориальные коды обрабатывать как категории.
- **Ограничения и результат:** Задать `time_limit = 600`, `num_gpus = 0`; запрос на сравнение моделей реализовать настройкой сервиса `return_leaderboard = true`. Лимит относится к обучению, а не гарантирует получение всех отчётов за 600 секунд.
- **Валидация:** Независимый стратифицированный случайный тест допустим как предварительная оценка; внутренняя валидация AutoGluon - `auto`. В файле нет дат и ID для подтверждения качества на будущих наборах студентов.

**Кандидат конфигурации** (после проверки момента доступности остальных признаков):

```json
{
  "label": "Target",
  "problem_type": "multiclass",
  "eval_metric": "f1_macro",
  "validation_procedure": "auto",
  "time_limit": 600,
  "num_gpus": 0,
  "presets": "medium_quality"
}
```

**Настройки сервиса для результата:**

```json
{
  "return_leaderboard": true
}
```

Время обучения и число GPU заданы пользователем; `presets = "medium_quality"` выбрано как профиль по умолчанию. `return_leaderboard` не передаётся в `fit()`. `validation_procedure` - параметр обёртки; она также должна отдельно выделить независимый тест.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент сохраняет `Target`, `multiclass`, `f1_macro`, `time_limit = 600`, `num_gpus = 0`, учитывает момент после второго семестра, проверяет доступность признаков и оформляет leaderboard как настройку сервиса.
- **Допустимые альтернативы:** разные допустимые профили обучения в рамках лимита; дополнительные метрики по классам и вопросы об актуальности финансовых признаков. Состав моделей и последовательность шагов не обязаны совпадать с эталоном.
- **Критические ошибки:** изменить явно названную метрику или тип задачи без согласования; использовать GPU либо превысить заданный лимит в конфигурации; передать `return_leaderboard` как параметр обучения; без проверки включить сведения, появившиеся после второго семестра.
