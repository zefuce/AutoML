# BS-01 - Прогноз спроса на следующий час без будущей погоды

**Датасет:** Bike Sharing (`hour.csv`)  
**Категория:** короткий  

## 1. Входные данные

**Запрос пользователя:**

> «Нужен спрос на велосипеды через час. Календарь знаю, фактическую погоду того часа — нет.»

**Вход для будущего теста:** исходный `hour.csv` вместе с приведённым выше текстом.

В тексте не названы имя столбца `cnt`, метрика и лимит обучения. Регрессия выводится из задачи прогнозирования количества аренд, а конкретный таргет устанавливается после анализа данных.

## 3. Ручное решение и конфигурация

- **Задача:** По EDA `cnt` - общее число аренд за час, 17 379 строк; `problem_type = "regression"`. Заранее известный календарь позволяет построить табличный прогноз на следующий час без использования его фактических показаний.
- **Признаки:** Исключить `casual` и `registered`: их сумма точно равна `cnt`; также исключить `instant` как идентификатор и фактическую погоду будущего часа (`weathersit`, `temp`, `atemp`, `hum`, `windspeed`). В кандидате `dteday` используется для разбиения, а календарь представлен `season`, `yr`, `mnth`, `hr`, `holiday`, `weekday`, `workingday`. Коды `yr` требуют проверки при использовании за пределами 2011-2012 годов.
- **Метрика:** `mean_absolute_error` - допустимый начальный выбор для ошибки в числе аренд, не указанный пользователем. `root_mean_squared_error` допустима, если важнее крупные промахи в пиковые часы.
- **Валидация и данные:** Разделить наблюдения по времени: поздние часы только для независимой оценки, ранние - для обучения и настройки. `validation_procedure = "auto"` относится лишь к внутренней валидации AutoGluon, не заменяет внешнее временное разбиение. По EDA в почасовой сетке отсутствуют 165 наблюдений: их нельзя автоматически принимать за нулевой спрос.

**Кандидат конфигурации** (после проверки указанных условий):

```json
{
  "label": "cnt",
  "problem_type": "regression",
  "eval_metric": "mean_absolute_error",
  "ignored_columns": [
    "instant",
    "dteday",
    "weathersit",
    "temp",
    "atemp",
    "hum",
    "windspeed",
    "casual",
    "registered"
  ],
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

Погодные измерения текущей строки нельзя использовать как известные заранее для следующего часа. Табличная модель по календарным признакам возможна без отдельного механизма прогнозирования временного ряда; при необходимости лагов нужна дополнительная подготовка данных. `time_limit` задаётся сервисом; `ignored_columns` и `validation_procedure` обрабатываются обёрткой.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент определяет `cnt` и регрессию, сохраняет горизонт следующего часа, исключает `casual` и `registered`, не использует фактическую погоду будущего часа, предлагает временную проверку и не заполняет отсутствующие часы нулями.
- **Допустимые альтернативы:** MAE или RMSE с обоснованием; использование `dteday` или лагов, если подтверждены их доступность и корректная подготовка; уточнение, какие календарные сведения и прогнозы доступны перед часом. Порядок действий агента не обязан совпадать с эталоном.
- **Критические ошибки:** обучить модель для следующего часа на фактической погоде этого часа или на `casual`/`registered`; проверять прогноз будущих часов случайным перемешиванием; считать отсутствие записи нулём спроса; выдавать `validation_procedure` за внешнее временное разделение.
