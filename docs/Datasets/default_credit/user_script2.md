# DC-02 - Приоритет выявления неплательщиков

**Датасет:** Default of Credit Card Clients (`default of credit card clients.xls`)  
**Категория:** опечатки  

## 1. Входные данные

**Запрос пользователя:**

> «Главное неплатильщиков не пропускать!! лишнии предупреждения переживем, но если модель скажет "все ок", а клиент не заплатит — плохо.»

**Вход для будущего теста:** исходный `default of credit card clients.xls` вместе с приведённым выше текстом.

Опечатки не меняют смысл запроса. Пользователь указывает приоритет ошибок, но не называет метрику `recall`, стоимость предупреждений или порог решения.

## 3. Ручное решение и конфигурация

- **Задача:** По данным выбрать `label = "default payment next month"`, `problem_type = "binary"`, положительный класс `1`. Доля класса `1` - 22,12%; постоянный прогноз класса `0` даст высокую `accuracy`, но пропустит все неплатежи.
- **Метрика:** `recall` для класса `1` - обоснованный начальный выбор из-за высокой цены пропусков. `precision` полезна как дополнительная оценка ложных тревог. Высокий `recall` сам по себе не гарантирует приемлемую долю предупреждений и не определяет порог автоматически.
- **Признаки:** Исключить `ID`; не считать коды `PAY_*`, `EDUCATION` и `MARRIAGE` непрерывными измерениями. Уточнить момент прогноза и проверить, какие сведения о предыдущих платежах доступны до него.
- **Валидация:** Использовать независимую предварительную стратифицированную выборку, контролируя и `recall`, и `precision`; внутренняя валидация AutoGluon - `auto`. Без новых периодов это не временная проверка.

**Кандидат конфигурации** (После уточнения момента прогноза и проверки признаков):

```json
{
  "label": "default payment next month",
  "problem_type": "binary",
  "positive_class": 1,
  "eval_metric": "recall",
  "extra_metrics": [
    "precision"
  ],
  "ignored_columns": [
    "ID"
  ],
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

`extra_metrics` относится к расчёту дополнительных показателей при оценке, а не к оптимизации `fit()`. Выбор рабочего порога и допустимого числа ложных предупреждений требует дополнительных бизнес-условий. `time_limit` назначается сервисом по умолчанию.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент распознаёт приоритет минимизации FN для класса `1`, предлагает `recall` и контроль `precision`, не ограничивается `accuracy` и не задаёт произвольный порог. Проверяет доступность признаков до момента прогноза.
- **Допустимые альтернативы:** другая обоснованная метрика или несколько метрик при сохранении приоритета пропусков; запрос допустимой частоты ложных предупреждений для выбора порога.
- **Критические ошибки:** оптимизация только `accuracy`; путаница между FP и FN или классами `0`/`1`; обещание нулевых пропусков; произвольный порог, выданный за требование пользователя; использование будущих платежей.
