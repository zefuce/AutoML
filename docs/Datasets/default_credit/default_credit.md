# Default of Credit Card Clients - результат исследования

**Задача.** Оценить вероятность невыполнения платежного обязательства по кредитной карте в следующем месяце на основании данных о клиенте и истории платежей. Момент формирования прогноза необходимо согласовать.

**Данные.** UCI Default of Credit Card Clients, исходный `default of credit card clients.xls`: 30 000 строк, 25 столбцов, из них 23 входных признака, идентификатор `ID` и таргет `default payment next month`. Источник и описание полей: [UCI Machine Learning Repository](https://archive.ics.uci.edu/dataset/350/default+of+credit+card+clients). Расчёты и графики приведены в `default_credit.ipynb`.

## 1. Первичный анализ

Таргет принимает значения `0` и `1`, поэтому исходная постановка - бинарная классификация. Все входные столбцы представлены числами, но часть значений обозначает категории.

### Смысл признаков

| Признак или группа | Что содержит | На что обратить внимание |
|---|---|---|
| `ID` | Идентификатор клиента | Не использовать как числовой предиктор |
| `LIMIT_BAL` | Кредитный лимит, новые тайваньские доллары | Большие значения, различия по классам |
| `SEX` | Код пола | Категориальный признак, связь с исходом не означает причинность |
| `EDUCATION` | Код образования | Значения `0`, `5`, `6` не раскрыты в базовом описании |
| `MARRIAGE` | Код семейного положения | Значение `0` не раскрыто в базовом описании |
| `AGE` | Возраст | Диапазон, крайние значения |
| `PAY_0`, `PAY_2`, `PAY_3`, `PAY_4`, `PAY_5`, `PAY_6` | Статусы платежей с сентября по апрель 2005 года | Категориальные коды, в данных есть `-2` и `0` |
| `BILL_AMT1` - `BILL_AMT6` | Суммы ежемесячных счетов | Отрицательные значения, корреляции соседних месяцев |
| `PAY_AMT1` - `PAY_AMT6` | Суммы внесённых платежей | Нули, асимметрия и большие значения |
| `default payment next month` | Невыполнение платежа в следующем месяце | Целевая переменная (`1` - да, `0` - нет) |

## 2. Таргет

| Класс | Количество | Доля |
|---|---:|---:|
| `0` | 23 364 | 77,88% |
| `1` | 6 636 | 22,12% |

Положительный класс составляет 22,12%. Постоянный прогноз `0` дал бы accuracy 77,88% и не обнаружил бы ни одного случая невыполнения платежа.

## 3. Пропуски и дубликаты

| Проверка | Результат |
|---|---:|
| Формальные `NaN` | 0 |
| Полные дубликаты строк | 0 |
| Повторы `ID` | 0 |
| Повторы строк без `ID`, включая таргет | 35 |
| Повторы наборов входных признаков без `ID` и таргета | 56 |
| Группы одинаковых входных признаков с разным таргетом | 21 |

Формальных пропусков нет. Для 21 группы одинаковых входных признаков исходы различаются. Совпадение характеристик не доказывает, что строки относятся к одному клиенту. 

## 4. Коды и диапазоны

| Показатель | Результат |
|---|---:|
| Возраст: минимум / медиана / максимум | 21 / 34 / 79 лет |
| `LIMIT_BAL`: минимум / медиана / максимум | 10 000 / 140 000 / 1 000 000 |
| `EDUCATION` с кодом `0`, `5` или `6` | 345 |
| `MARRIAGE = 0` | 54 |
| Отрицательных `BILL_AMT1` | 590 |
| Нулевых `PAY_AMT1` | 5 249 |
| Отрицательных `PAY_AMT1` | 0 |

В исходных данных встречаются коды, которых нет в основной расшифровке UCI: `EDUCATION = 0, 5, 6`; `MARRIAGE = 0`; `PAY_* = -2, 0`. Количество статусов по каждому из шести месячных признаков приведено в ноутбуке. Без уточнения смысла такие коды не объединяются и не исправляются. Отрицательная сумма счёта сама по себе не устанавливает ошибку.

## 5. Числовые распределения и выбросы

Для предварительного поиска необычных значений IQR применён к возрасту, кредитному лимиту и сумме счёта за последний месяц.

| Признак | Медиана | IQR-сигналы | Доля строк |
|---|---:|---:|---:|
| `AGE` | 34 | 272 | 0,91% |
| `LIMIT_BAL` | 140 000 | 167 | 0,56% |
| `BILL_AMT1` | 22 381,5 | 2 400 | 8,00% |

У сумм счетов и платежей наблюдаются асимметричные распределения. Коды статусов `PAY_*` не проверяются общим IQR.

## 6. Категориальные признаки и связь с таргетом

Проценты означают долю `1` внутри соответствующей группы.

| Признак | Наблюдение | Особенность |
|---|---|---|
| `SEX` | Код `1`: 24,17% (11 888 клиентов); `2`: 20,78% (18 112) | Корреляция не устанавливает влияния пола |
| `EDUCATION` | Код `1`: 19,23% (10 585); `2`: 23,73% (14 030); `3`: 25,16% (4 917) | Есть нерасшифрованные и редкие коды |
| `MARRIAGE` | Код `1`: 23,47% (13 659); `2`: 20,93% (15 964) | Группы различаются по размеру |
| `PAY_0` | Код `0`: 12,81% (14 737); `1`: 33,95% (3 688); `2`: 69,14% (2 667) | Для редких кодов оценки менее устойчивы |

Для остальных статусов `PAY_2` - `PAY_6` в ноутбуке приведены отдельные таблицы количества клиентов и доли класса `1`. Связь задержек платежей с будущим невыполнением обязательств выражена сильнее, чем различия по отдельным демографическим кодам.

## 7. Числовые признаки и корреляции

Медиана кредитного лимита составляет 150 000 для класса `0` и 90 000 для класса `1`. Корреляции Пирсона рассчитаны для 14 количественных признаков без кодов категорий:

| Признак | Корреляция с таргетом |
|---|---:|
| `LIMIT_BAL` | −0,154 |
| `PAY_AMT1` | −0,073 |
| `BILL_AMT1` | −0,020 |
| `AGE` | 0,014 |

Попарные корреляции: `BILL_AMT1` с `BILL_AMT2` - 0,951; `PAY_AMT1` с `PAY_AMT2` - 0,286. Коды `SEX`, `EDUCATION`, `MARRIAGE` и `PAY_*` не включались в корреляционный анализ как непрерывные значения. Для статусов платежей в ноутбуке приведены таблицы долей классов и сочетаний статусов.

## 8. Момент прогноза и ограничения данных

В файле представлены характеристики клиентов и история платежей с апреля по сентябрь 2005 года. `PAY_0` относится к сентябрю, `PAY_2` - к августу, `PAY_6` - к апрелю. Данные не содержат последовательных записей одного клиента за разные прогнозные периоды.

Для корректной постановки необходимо определить момент прогноза и убедиться, что сведения за соответствующие месяцы уже доступны. Нет достаточных временных полей для проверки качества на последующих периодах.

## 9. Итоги и эталон ожидаемых действий агента

| Что нужно решить | Обоснованный ориентир |
|---|---|
| Что предсказывать | `default payment next month`, класс `1` |
| Тип задачи | Бинарная классификация |
| Дисбаланс | Учитывать 22,12% положительных наблюдений |
| Пропуски | Формальных `NaN` нет; отдельно интерпретировать неизвестные коды категорий |
| Идентификатор | Не использовать `ID` как содержательный предиктор |
| Категории | Не трактовать коды `SEX`, `EDUCATION`, `MARRIAGE`, `PAY_*` как непрерывные величины |
| Ошибки и выбросы | Не удалять большие лимиты и отрицательные суммы счетов только по IQR |
| Момент прогноза | Уточнить дату среза и доступность всей истории платежей |
| Метрика | Выбирать с учётом цены пропущенных невыполнений платежа и ложных предупреждений; рассматривать PR-AUC, recall, precision |
| Валидация | Не считать случайное разбиение проверкой на будущих месяцах без соответствующих дат |
