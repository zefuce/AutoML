# DC-04 - Оценка риска с ограничением ресурсов и важностью признаков

**Датасет:** Default of Credit Card Clients (`default of credit card clients.xls`)  
**Категория:** длинный, ограничения  

## 1. Входные данные

**Запрос пользователя:**

> «Я делаю небольшой прототип для отдела кредитных рисков. Работаем на обычном сервере, поэтому выделить можно не более двух ядер CPU и совсем без GPU. Обучение не должно идти дольше пяти минут. Хотелось бы получить оценку вероятности неплатежа в следующем месяце, а после запуска увидеть, какие признаки модель считает важными. Не нужно обещать, что это автоматически объяснит причины невозврата кредита; меня устроит технический отчет. Посмотри, какие параметры AutoML и какие настройки выдачи результатов для этого подходят.»

**Вход для будущего теста:** исходный `default of credit card clients.xls` вместе с приведённым выше текстом.

## 3. Ручное решение и конфигурация

- **Задача:** `label = "default payment next month"`, `problem_type = "binary"`, положительный класс `1`. Для выдачи вероятности класса `1` сервис использует вероятностные предсказания модели, а не только метки `0` и `1`.
- **Ограничения:** `time_limit = 300`, `num_cpus = 2`, `num_gpus = 0`. Время расчёта важности признаков дополнительно к времени обучения; нельзя обещать, что вся процедура вместе с отчётом завершится за пять минут.
- **Метрика:** `log_loss` - допустимый начальный выбор для вероятностного прогноза, не указанный пользователем. `roc_auc` возможна как альтернатива для оценки ранжирования; ни одна из этих метрик сама по себе не гарантирует калибровку вероятностей.
- **Данные и валидация:** Исключить `ID`, корректно обработать категориальные коды и проверить наличие истории платежей на момент прогноза. Для предварительной оценки возможен независимый стратифицированный тест; проверка на будущих месяцах требует других данных.
- **Результат:** В настройках сервиса предусмотреть `return_feature_importance = true`. Важность признаков отражает вклад в качество прогнозов при выбранном способе оценки, но не доказывает причины невозврата кредита.

**Кандидат конфигурации** (После проверки момента прогноза и доступности признаков):

```json
{
  "label": "default payment next month",
  "problem_type": "binary",
  "positive_class": 1,
  "eval_metric": "log_loss",
  "ignored_columns": [
    "ID"
  ],
  "validation_procedure": "auto",
  "time_limit": 300,
  "presets": "medium_quality",
  "num_cpus": 2,
  "num_gpus": 0
}
```

**Настройки сервиса для результата:**

```json
{
  "return_feature_importance": true
}
```

Вероятность класса `1` выдаётся через вероятностный интерфейс предсказания, а важность признаков - отдельной операцией сервиса. `return_feature_importance` не является параметром `fit()`. `time_limit` ограничивает обучение, но не гарантирует общий срок получения отчёта.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент определяет класс `1`, учитывает `time_limit = 300`, `num_cpus = 2`, `num_gpus = 0`, предусматривает вероятности, а важность признаков относит к настройкам сервиса. Не выдаёт важность за причинное объяснение и не обещает общий пятиминутный срок.
- **Допустимые альтернативы:** `roc_auc` или другая обоснованная бинарная метрика вместо `log_loss`; дополнительные проверки качества вероятностей и уточнение момента доступности истории платежей.
- **Критические ошибки:** превышение выделенных ресурсов в конфигурации; отсутствие вероятностного результата; попытка передать `return_feature_importance` в `fit()`; причинная трактовка важности признаков; объявление лимита обучения гарантией времени всей обработки.
