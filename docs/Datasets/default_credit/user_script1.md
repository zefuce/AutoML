# DC-01 - Прогноз невыполнения платежа в следующем месяце

**Датасет:** Default of Credit Card Clients (`default of credit card clients.xls`)  
**Категория:** короткий  

## 1. Входные данные

**Запрос пользователя:**

> «По этой истории платежей можно предсказывать, кто не заплатит в следующем месяце?»

**Вход для будущего теста:** исходный `default of credit card clients.xls` вместе с приведённым выше текстом.

## 3. Ручное решение и конфигурация

- **Задача:** По датасету цель соответствует `label = "default payment next month"`, `problem_type = "binary"`, положительный класс `1` (невыполнение платежа). По EDA класс `1` занимает 22,12% наблюдений, поэтому одна `accuracy` недостаточна для оценки выявления неплатежей.
- **Признаки:** Исключить `ID`; коды `SEX`, `EDUCATION`, `MARRIAGE`, `PAY_*` не трактовать как непрерывные измерения. Неизвестные коды категорий не исправлять произвольно. Проверить, что история `PAY_*`, `BILL_AMT*`, `PAY_AMT*` уже известна на момент прогноза.
- **Метрика:** `roc_auc` - обоснованный начальный выбор для оценки ранжирования рисков, не заданный пользователем. При наличии бизнес-приоритетов можно дополнительно оценивать `recall` и `precision`; порог решения без таких условий не фиксировать.
- **Валидация:** Для предварительной оценки возможно внешнее стратифицированное случайное разбиение, внутренняя валидация AutoGluon - `auto`. Такая проверка не доказывает качество на будущих месяцах: в файле нет последовательных прогнозных периодов.

**Кандидат конфигурации** (После уточнения момента формирования прогноза и проверки доступности признаков):

```json
{
  "label": "default payment next month",
  "problem_type": "binary",
  "positive_class": 1,
  "eval_metric": "roc_auc",
  "ignored_columns": [
    "ID"
  ],
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

`time_limit` пользователь не указал: перед обучением сервис подставляет свой лимит. `ignored_columns` и `validation_procedure` преобразуются обёрткой, а не передаются в `fit()` как одноимённые аргументы.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент определяет `default payment next month`, `binary`, класс `1`; исключает `ID`, проверяет доступность истории платежей и корректно трактует закодированные категории. Не представляет случайное разбиение как тест на следующих месяцах.
- **Допустимые альтернативы:** `roc_auc`, `recall`, `f1` или другая обоснованная бинарная метрика при объяснённой цели; уточняющий вопрос о дате прогноза до окончательного решения. Точный порядок проверок не важен.
- **Критические ошибки:** прогнозирование класса `0` вместо риска неплатежа; использование `ID` как количественного предиктора; обучение на платежах, ещё неизвестных в момент прогноза; выдача случайной проверки за временную.
