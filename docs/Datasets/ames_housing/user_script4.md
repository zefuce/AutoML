# AH-04 - Несовместимая метрика accuracy для регрессии

**Датасет:** Ames Housing (`train.csv`)  
**Категория:** ошибочная метрика  

## 1. Входные данные

**Запрос пользователя:**

> «Сделай регрессию по `SalePrice`, а качество считай через `accuracy`. Никакие другие метрики мне не нужны.»

**Вход для будущего теста:** исходный `train.csv` вместе с приведённым выше текстом.

## 2. Ручной анализ запроса

Результат извлечения требований из текста:

```json
{
  "goal": {
    "value": "обучить регрессионную модель для предсказания SalePrice",
    "status": "explicit"
  },
  "task_type": {
    "value": "regression",
    "status": "explicit"
  },
  "target": {
    "value": "SalePrice",
    "status": "explicit"
  },
  "metric": {
    "value": "accuracy",
    "status": "explicit"
  },
  "constraints": {
    "training_time": {
      "value": null,
      "status": "unknown"
    }
  },
  "requirements": {
    "metric_exclusivity": {
      "value": "никакие метрики, кроме accuracy, не использовать",
      "status": "explicit"
    }
  },
  "conflicts": [
    "Для регрессии по SalePrice указана классификационная метрика accuracy, а использование других метрик запрещено."
  ]
}
```

Пользователь явно задал таргет, тип задачи и метрику. Конфликт обнаруживается при проверке совместимости требований: `accuracy` в конфигурации проекта используется для классификации, а не регрессии.

## 3. Ручное решение и конфигурация

- **Задача:** `label = "SalePrice"`, `problem_type = "regression"` согласуются с EDA: таргет - непрерывная цена продажи в долларах. Изменять регрессию на классификацию только ради `accuracy` нельзя.
- **Конфликт:** `eval_metric = "accuracy"` несовместима с `regression` в поддерживаемой конфигурации AutoGluon. Не передавать такое сочетание на обучение и не подменять метрику молча.
- **Возможное решение:** предложить `mean_absolute_error` или `root_mean_squared_error` с пояснением ошибок в долларах. Поскольку пользователь запретил другие метрики, запросить согласие на замену; до этого обучение остановить.
- **Другие проверки:** после разрешения конфликта исключить `Id`, проверить смысл пропусков и момент доступности признаков. Эти действия не устраняют ошибку метрики.

**Кандидат конфигурации:** не формируется до уточнения запроса и устранения существенных неопределённостей.

Для этой исходной формулировки корректная финальная конфигурация не существует. После согласования метрики можно составить конфигурацию регрессии по `SalePrice`, но `accuracy` в ней быть не должно.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент сохраняет явно заданные `SalePrice` и регрессию, обнаруживает несовместимость `accuracy`, объясняет ошибку и запрашивает разрешение использовать регрессионную метрику без запуска обучения.
- **Допустимые альтернативы:** предложить MAE либо RMSE; спросить, имел ли пользователь в виду долю прогнозов в заданном диапазоне погрешности, пояснив, что это уже другой, отдельно определяемый показатель, а не штатная `accuracy` для регрессии.
- **Критические ошибки:** передать `accuracy` в регрессионный `eval_metric`; незаметно сменить метрику или тип задачи; сформировать и запустить некорректную конфигурацию, проигнорировав запрет альтернативных метрик.
