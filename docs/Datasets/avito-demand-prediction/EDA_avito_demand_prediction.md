# Avito Demand Prediction - результат исследования

Задача исследования - изучить объявления Avito и определить особенности данных, влияющие на настройку AutoML для прогноза `deal_probability`. Целевая переменная числовая и принимает значения от 0 до 1. В рамках исследования рассматривается регрессия.

Данные: [Avito Demand Prediction (Kaggle)](https://www.kaggle.com/competitions/avito-demand-prediction/data). Все показатели и графики рассчитываются в `EDA_avito_demand_prediction.ipynb`

Для воспроизведения необходимы архивы [train.zip](https://drive.google.com/file/d/1m21RAnI2Y4lp3xKptsgFlhWzO_p__AkL/view?usp=drive_link), [test.zip](https://drive.google.com/file/d/1JRCjD_iyju0Fh9NtB_WekKxuO3oE_Pgf/view?usp=drive_link), [train_active.zip](https://drive.google.com/file/d/1old2ma3Ks_KOG7Z_-AwZ_ZR4QKREisRR/view?usp=drive_link), [test_active.zip](https://drive.google.com/file/d/13o-l3huxjHvFtZx2VM-GO8UW5ZqhKXve/view?usp=drive_link), [periods_train.zip](https://drive.google.com/file/d/1AUIoJ_ptI4Id6963LSm-_UQBUydRruhP/view?usp=drive_link), [periods_test.zip](https://drive.google.com/file/d/1MaX6YHuESEi0iWa17l-B5tc3lE8ev5kW/view?usp=drive_link).

### Ограничения качества дополнительных данных

В обеих таблицах `*_active` обнаружено ровно 65 536 строк без `region`, `city` и `parent_category_name`. Кроме того, `activation_date` отсутствует у 124 323 строк `train_active` и 114 518 строк `test_active`; в `parent_category_name` по одной записи имеет нетипичное значение `Private`. Наличие таких наблюдений подтверждено агрегатами потокового анализа, но по ним нельзя определить, связаны ли они с исходным содержимым, особенностями экспорта или чтения CSV. Требуется адресная проверка исходных записей.

### Диагностика аномалий

В каждом из `*_active` все 65 536 строк без `region` принадлежат одному продавцу с `user_id = 682fde61552c`. В пяти выведенных примерах совпадает и `item_id = 96f74c88e2fd`; идентичность `item_id` во всех 65 536 строках отдельно не подсчитывалась. В обоих файлах также обнаружено по одной записи с нетипичной категорией `Private` и смещёнными значениями полей. Это подтверждает локальную аномалию записей, но не устанавливает её происхождение.

### Сопоставление снимков и временная доступность

| Показатель | train_active | test_active |
|---|---:|---:|
| Первая дата в `activation_date` | 2017-03-15 | 2017-04-12 |
| Записей с первой датой | 12 246 008 | 11 815 353 |
| Доля среди записей с известной датой | 87,44% | 92,96% |

Между `train_active` и `test_active` совпадают 8 928 589 уникальных `item_id`, но диапазоны непустых `activation_date` в этих таблицах не пересекаются. Следовательно, для совпадающего объявления при наличии обеих дат они различаются между снимками. Без дополнительных сведений о семантике поля нельзя считать его неизменной датой первоначального размещения объявления.

Совпадение `user_id` с размеченными данными само по себе не означает доступность полного содержимого объявления или периода активности на дату прогноза. В ноутбук добавлены проверка совпадающих объявлений на фиксированной подвыборке и консервативная оценка покрытия истории продавца: учитываются только заполненные записи с `activation_date` строго раньше первой размеченной записи продавца. Эта оценка проверяет порядок записанных дат, но не подтверждает историческую доступность содержимого.

### Решение по вспомогательным таблицам

| Таблица | Решение для основного AutoML-эксперимента | Основание |
|---|---|---|
| `train` | Использовать для обучения | Есть `deal_probability` |
| `test` | Использовать для прогноза | Те же признаки, целевая переменная отсутствует |
| `train_active`, `test_active` | Не присоединять | Нет общих `item_id` с основными таблицами; историческая доступность признаков по `user_id` не подтверждена |
| `periods_train`, `periods_test` | Не присоединять | Связаны с `*_active`, содержат повторные интервалы и могут включать события после даты целевого объявления |

Четыре вспомогательные таблицы не бесполезны: `*_active` могут служить источником агрегатов по `user_id` (число предыдущих объявлений, медиана цены, доли категорий), а `periods_*` после связи со своим `*_active` по `item_id` - числа периодов и длительности активности. Эти признаки могли бы обогатить основную таблицу через `user_id`, а не через `item_id`. Однако для каждой целевой строки требуется доказать, что исходные объявления и события уже были доступны на её дату, устранить повторные ключи и исключить будущие периоды. Даты `activation_date` в `*_active` нельзя без дополнительного подтверждения трактовать как неизменные даты создания объявлений. Поэтому четыре вспомогательные таблицы исследованы, но не используются в базовом AutoML-эксперименте; возможность отдельного эксперимента с историческими признаками сохраняется.


## 9. Риски утечек и ограничения интерпретации

- Для будущих объявлений требуется временная валидация по `activation_date`. Пересечения `user_id` между частями дополнительно проверяются при оценке работы на новых продавцах.
- Дополнительные объявления и периоды нельзя напрямую присоединять к `train` и `test` по `item_id`: идентификаторы не совпадают. В `*_active` существуют повторные ключи.
- Значительные пересечения `*_active` между временными частями и несовпадающие диапазоны дат не позволяют без проверки использовать исторические атрибуты как признаки, известные в момент прогноза.
- Интервалы `periods_*` необходимо ограничивать датой прогноза. Суммарная длительность, вычисленная по полным будущим интервалам, потенциально содержит утечку.
- Причина аномальных строк `*_active` по сохранённым агрегатам неизвестна. Для базовой модели этот риск устранён исключением вспомогательных таблиц; диагностика конкретных записей добавлена в ноутбук.
- CSV содержит идентификатор `image` и категорию `image_top_1`, но не сами изображения. Качество на публичном `test` без размеченной цели не измеряется.

## 10. Ожидаемые действия AutoML-агента

1. Определить числовую цель `deal_probability` и регрессию без перевода значений в классы.
2. Учитывать концентрацию нулей и выбирать метрику по постановке пользователя.
3. Исследовать структурные пропуски, категориальные параметры, тексты и крайние цены.
4. При прогнозе будущих объявлений применять временную валидацию; при обобщении на новых продавцов отдельно проверять групповой сценарий.
5. Учитывать различия train/test и отсутствие истинной цели в test.
6. Не использовать `item_id` как обучающий признак; исключать идентификаторы изображений, если они не обеспечены соответствующим содержимым.
7. В основной конфигурации использовать `train` и `test` без `*_active` и `periods_*`. Дополнительные данные допустимы только для отдельной проверенной point-in-time схемы признаков по продавцам.
8. Не формировать агрегаты из будущих периодов и не размножать объявления соединением с повторяющимися `item_id`.

## Итог

Avito Demand Prediction нужна для проверки конфигурации регрессионного AutoML на числовых, категориальных и текстовых признаках, а также выбора временной или групповой валидации. По результатам EDA для базового эксперимента определены две необходимые таблицы: `train` для обучения и `test` для прогноза. Четыре вспомогательные таблицы изучены и обоснованно исключены из основной схемы из-за неподтверждённой исторической доступности данных. Вывод аномальных строк в ноутбуке позволил установить концентрацию пропусков у одного продавца; причина появления записей в исходных CSV остаётся неизвестной и не меняет решения для базового эксперимента.
