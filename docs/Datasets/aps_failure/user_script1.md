# APS-01 - Обнаружение отказов APS без пропусков

**Датасет:** APS Failure (`aps_failure_training_set.csv`)  
**Категория:** короткий  

## 1. Входные данные

**Запрос пользователя:**

> «Не пропускай поломки APS.»

**Вход для будущего теста:** исходный `aps_failure_training_set.csv` вместе с приведённым выше текстом.

## 3. Ручное решение и конфигурация

- **Задача:** `label = "class"`, `problem_type = "binary"`, положительный класс `pos` (неисправность APS). По EDA в обучающей части 1 000 объектов `pos` из 60 000 (1,67%); обычная `accuracy` может скрывать пропуски отказов.
- **Метрика:** `recall` - обоснованный начальный выбор для повышения обнаружения класса `pos`, но пользователь её не называл. Дополнительно оценивать ложные тревоги и, при подтверждении стоимости ошибок, общие потери: максимальный `recall` сам по себе не гарантирует полезную модель.
- **Пропуски и признаки:** В CSV `na` обозначает отсутствующее значение; по EDA пропущено 8,33% ячеек признаков, полностью заполнена только 591 строка. Не удалять автоматически все неполные строки. Проверить почти пустые и почти постоянные признаки, не приписывать анонимизированным столбцам физический смысл.
- **Валидация:** Официальный `aps_failure_test_set.csv` сохранить для независимой оценки, если сервис умеет принимать отдельный тестовый файл. Для обучения и предварительной проверки возможна стратификация; `validation_procedure = "auto"` относится только к внутренней валидации AutoGluon. Временные отношения между файлами не установлены.

**Кандидат конфигурации** (после проверки момента прогноза и доступности используемых показателей):

```json
{
  "label": "class",
  "problem_type": "binary",
  "positive_class": "pos",
  "eval_metric": "recall",
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

Это начальная конфигурация для обнаружения отказов, а не гарантия отсутствия FN. `time_limit` пользователь не задал: перед обучением сервис подставляет лимит по умолчанию; обработка `na` выполняется при подготовке данных. Отдельная тестовая выборка и `validation_procedure` не являются одним и тем же.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент определяет `class`, `binary` и `pos`, распознаёт приоритет снижения FN и дисбаланс 1,67%, правильно обрабатывает `na` и обосновывает выбор метрики, учитывая ложные тревоги.
- **Допустимые альтернативы:** другая метрика или набор метрик с явным контролем пропущенных отказов; уточнение момента принятия решения и допустимой цены лишних проверок. Порядок действий не должен совпадать с эталоном.
- **Критические ошибки:** выбирать модель только по `accuracy`; считать `neg` положительным классом; удалять все строки с `na`; обещать нулевое число пропущенных отказов на новых данных.
