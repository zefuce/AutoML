# APS-03 - Независимая оценка на отдельном тестовом файле

**Датасет:** APS Failure (`aps_failure_training_set.csv`)  
**Категория:** длинный  

## 1. Входные данные

**Запрос пользователя:**

> «В архиве, который я приложил, кажется, уже есть отдельная таблица для тестирования. Хочу, чтобы вы сначала работали только с обучающей частью: посмотрели пропуски, проверили типы столбцов и настроили предсказание отказов пневматической системы. А финальную проверку оставьте на том отдельном тестовом файле, не заглядывая в его ответы ради выбора параметров. Если там окажется другая структура или не будет признаков, скажите об этом. И не нужно утверждать, что это проверка на будущих месяцах: в моем описании вообще нет дат наблюдений.»

**Вход для будущего теста:** исходные `aps_failure_training_set.csv` и `aps_failure_test_set.csv` вместе с приведённым выше текстом.

## 3. Ручное решение и конфигурация

- **Задача:** По EDA целевой столбец `class` (`neg`/`pos`), постановка - `binary`, положительный класс `pos`. `aps_failure_training_set.csv` содержит 60 000 строк, официальный `aps_failure_test_set.csv` - 16 000.
- **Проверка данных:** В обучающей части распознать строковый код `na` как пропуск, проверить числовые типы и особенности анонимизированных признаков. По EDA оба файла имеют 171 столбец, их названия и порядок совпадают; перед применением подтвердить совместимость набора признаков без использования тестовых меток для настройки.
- **Разделение:** Обучать и выбирать модели только на `aps_failure_training_set.csv` с внутренней валидацией. `aps_failure_test_set.csv` сохранить для однократной независимой итоговой оценки: не подбирать по нему признаки, параметры, модель или порог. В таблицах нет явной временной метки; тест нельзя называть проверкой на следующих месяцах.
- **Метрика и ограничения:** `roc_auc` - допустимый предварительный выбор для несбалансированной бинарной задачи, не указанный пользователем. В проектном базовом режиме входом служит одна размеченная таблица; полноценное подключение внешнего тестового файла возможно только при реализованной поддержке сервиса либо в отдельной процедуре оценки.

**Кандидат конфигурации** (для обучения на тренировочном файле, без подключения внешнего теста):

```json
{
  "label": "class",
  "problem_type": "binary",
  "positive_class": "pos",
  "eval_metric": "roc_auc",
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

`validation_procedure = "auto"` описывает внутреннюю валидацию на обучающих данных, а не способ передачи отдельного тестового CSV. Если загрузка независимого теста сервисом не реализована, агент должен сообщить об этом и не обещать выполненную итоговую оценку; `time_limit` задаётся сервисом.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент определяет `class`, `binary` и `pos`, использует тренировочный файл для настройки, распознаёт `na`, проверяет схему и сохраняет официальный тест для независимой оценки. Не утверждает, что тест расположен в будущем.
- **Допустимые альтернативы:** иная обоснованная основная метрика при контроле редкого класса; дополнительное внутреннее разбиение train; сообщение о необходимости расширить сервис для второго файла.
- **Критические ошибки:** обучать или выбирать параметры по тестовым ответам; считать `validation_procedure` автоматической поддержкой внешнего теста; молча объединять оба файла; объявлять тест временным без дат либо игнорировать несовпадающие признаки.
