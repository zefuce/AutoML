# Т-Банк: Воронка авиабилетов - результат исследования

Задача исследования - изучить сессии пользователей сервиса Авиа и определить особенности данных, влияющие на настройку AutoML для прогноза успешной покупки. Исходный файл содержит отдельные посещения экранов. Целевая переменная не представлена готовым столбцом на уровне сессии и должна определяться по статусам покупки.

Источник: DANO, предоставленные `Воронка авиабилетов.pdf` и `dano_dataset_avia_hashed_corrected_s.xlsx`. Все показатели и графики рассчитаны в `EDA_tbank_avia_funnel.ipynb`.

Для воспроизведения необходим файл [dano_dataset_avia_hashed_corrected_s.xlsx](https://docs.google.com/spreadsheets/d/1upjVtIJaSdl4Rn5jgCV6N1KOq0SqxHEf/edit?usp=drive_link&ouid=104970778427981791604&rtpof=true&sd=true), размещённый рядом с ноутбуком.

Для построения обучающей выборки требуется правило обработки этих случаев.

В `session_source` и `session_channel` значение `Неизвестно` встречается по 121 236 раз (49,62% событий). Это содержательный специальный код, не распознаваемый `isna()`. Среди платформ встречаются `ios` (137 206 строк), `android` (106 721), `ubuntu` (207) и 211 пропусков. Утверждать, что `ubuntu` ошибочен, без сведений о сборе данных нельзя.

Поля результата покупки почти всегда пустые, что согласуется с их назначением. Использовать заполненность этих полей как признаки для прогноза на входе в сессию нельзя.

## 9. Граница прогноза и доступность признаков

Для прогноза в начале сессии потенциально допустимы известные на входе сведения: устройство, источник, канал и дата начала, а также подтверждённо исторические признаки клиента. События посещения экранов, зафиксированные после начала сессии, и `session_purchase_*` не должны входить в признаки.

Если прогноз проводится после поиска либо после просмотра выдачи, потребуется отдельно определить момент среза и агрегировать только уже произошедшие события. `session_id` служит ключом построения одной строки на сессию, `client_id` - связью с историей и основанием для групповой валидации; как технические идентификаторы они не должны автоматически становиться обучающими признаками.

## 10. Выводы для настройки AutoML

1. Определять целевой объект как сессию, а не отдельную строку экрана.
2. Формировать бинарную цель по подтверждённому успеху и отдельно разрешать 143 сессии с ценой без подтверждённого статуса.
3. Учитывать долю подтверждённых успехов 6,13% при выборе метрики с учётом бизнес-ошибок.
4. Исключать события после выбранного момента прогнозирования и поля `session_purchase_*`.
5. Проверять специальные значения `Неизвестно`, категории устройств, пропуски и различия сегментов.
6. Для будущих сессий использовать хронологическую валидацию; для новых клиентов дополнительно проверять групповое разделение.
7. Подтверждать историческую доступность клиентских агрегатов и не использовать сведения о будущих заказах.
8. Не трактовать наблюдаемую связь источника, сегмента или экранов с покупкой как причинный эффект.

## Итог

Т-Банк «Воронка авиабилетов» позволяет проверить конфигурацию AutoML для бинарной классификации при сессионных данных, разреженном положительном исходе, повторяющихся клиентах, неизвестных статусах и прямом риске утечки из последующих экранов. Исходный Excel проанализирован полностью; для подготовки корректной размеченной витрины необходимо установить момент прогноза и правила обработки неизвестных исходов. Без этих условий нельзя утверждать, что все сессии без статуса - отрицательные примеры.
